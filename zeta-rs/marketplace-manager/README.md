# zeta-marketplace-manager

`zeta-marketplace-manager` is Zeta's in-process, profile-local owner for Marketplace package
lifecycle. It is a library crate linked into App Server, not an executable and not part of the
remote Marketplace repository.

Canonical cross-crate ownership is documented in
[Marketplace integration](../../docs/marketplace-integration.md). This README owns the crate's exact
storage and lifecycle contract.

## Ownership

```text
App Server Marketplace RPC
  → MarketplaceManager
      ├─ MarketplaceRegistryClient: remote search/get/verified download
      ├─ Store: local artifacts + atomic manager-state.json
      ├─ installations: install/update/uninstall/listInstalled
      └─ runtime leases: acquire/release/openResource
```

| Responsibility | Manager |
| --- | --- |
| remote TUF, catalog, ZIP and download URL | ❌ delegated to injected registry client |
| local artifact materialization and digest recheck | ✅ |
| durable immutable installation records | ✅ |
| update and deferred uninstall | ✅ |
| capability references, leases and opaque resource reads | ✅ |
| permission, OAuth, activation and execution | ❌ product runtime |

## Key private symbols

| Symbol | Contract |
| --- | --- |
| `MarketplaceManager::open` | opens one profile root and injects a remote registry port |
| `MarketplaceManager::install_downloaded` | creates immutable installation/capability identities from a verified payload |
| `Store::materialize` | copies into Manager-owned staging, recomputes normalized digest and atomically persists the artifact |
| `DurableState` / `InstallationRecord` | authoritative local installation projection in `manager-state.json` |
| `RuntimeState` / `LeaseRecord` | process-local leases; never persisted across restart |
| `MarketplaceManager::local_capability_sources` | revalidates a complete immutable artifact before a trusted in-process runtime receives a private host handle |
| `activation::acquire_spec` | converts stored capability data into path-free Skill/MCP/Connector/Language/Executable activation contracts |
| `activation::open_resource` | reads lease-authorized opaque resources with bounded safe paths |

Installations are immutable. Updating A installs B, then removes A immediately or marks it
`pendingRemoval` while A has leases. Restart drops stale runtime leases and completes persisted
pending removals. Uninstalling does not currently garbage-collect an unreferenced artifact; retained
artifacts act as a verified local cache.

Architectural drift includes spawning a Manager child process, accepting remote cache paths,
exposing artifact paths through DTOs, parsing TUF/catalog metadata here, or activating capabilities
inside install/acquire.

## Verification

```bash
cargo test -p zeta-marketplace-manager
cargo clippy -p zeta-marketplace-manager --all-targets -- -D warnings
```

For a distribution generated by `../marketplace/tools/marketplace-tool`, the cross-repository smoke
path is:

```bash
cargo run -p zeta-marketplace-manager --example local_distribution_smoke -- \
  <distribution-root> <trusted-root.json> <temporary-state-root>
```

Current capability acquisition supports Skill, remote MCP, Connector, Language manifest and
Executable entrypoint contracts. Theme and generic asset activation remain unsupported until their
domain-specific path-free runtime contracts exist.
