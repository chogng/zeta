# `zui-demo`

`zui-demo` is a framework-only host smoke test. It composes a `zeta-ui::ActionBar` with a local `zui::ui::Icon`, submits the resulting `UiScene` through the `zui::render::Renderer` contract, and uses an in-memory recording backend. The reusable view observes a `zui::ui::ViewState<bool>` through a `ComponentRuntime`, so the same host also verifies stable component identity, retained subscriptions, and redraw invalidation. It intentionally has no dependency on `app`, commands, terminal sessions, App Server state, `zeta-icons`, `winit`, or `wgpu`.

The crate is not a production application. Its purpose is to keep the portability claim executable: if a reusable component starts requiring product state or a platform backend, this host should fail to remain small and dependency-neutral.

The optional `zui-native-demo` binary is a second application consuming only the capability-oriented `zui::app`, `zui::task`, `zui::services`, `zui::window`, and `zui::ui` public namespaces. Its builder fixes an application name, semantic version, application locale, Linux desktop identity, and pre-ready `SessionData` override; the first lifecycle callback verifies the shared metadata, locale and preferred-language views, app directory, executable, temporary, and session paths. Its product constructor starts an owned `ApplicationHandle::when_ready` wait before the event loop becomes ready, then it opens framework-owned root/child windows through startup and the cross-thread-capable application proxy, enumerates product-window relationships, exercises connected-display identity/point/rectangle queries, redraws all windows after a display-change callback, routes retained-handle close through `WindowEvent::CloseRequested`, and accepts normal exits through the cancellable `App::before_exit` lifecycle point. The application menu also exercises `AppContext::relaunch` followed by a separate normal exit, so a relaunched single-instance primary starts only after the old primary releases ownership. Each window owns its component runtime, while shared view-state subscriptions drive redraw invalidation. The app also runs a scoped background task and event-loop timer, installs a checkbox/accelerator/native-role application menu, tray item and global shortcut, opens parented file/message dialogs from menu actions, injects non-mutating protocol-client, login-item, application-badge, file-icon, and Jump List backends and exercises their context APIs without changing host OS state, acquires a desktop single-instance identity, forwards later argv/cwd/opaque data to `App::second_instance`, restores native application focus using platform-specific Electron semantics, accepts native file drops, macOS application activation/open-file requests, and `zui-demo://` launch or forwarded URLs, publishes the frame through AccessKit, and uses the default wgpu backend through `zui` while keeping the default headless test path unchanged. Parent-window and native display-notification smoke coverage is enabled on macOS and Windows; Linux uses bounded topology polling while unsupported parent, global work-area, and rotation semantics remain explicit.

Verification:

```text
cargo test -p zui-demo
cargo run -p zui-demo
cargo check -p zui-demo --features native --bin zui-native-demo
cargo run -p zui-demo --features native --bin zui-native-demo
```
