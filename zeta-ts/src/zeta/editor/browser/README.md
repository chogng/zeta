# Stanza Editor browser layer

> 行式文本编辑器的 canonical 设计规范见 [`text-engine.md`](../text-engine.md)，文本几何与浏览器渲染后端的长期目标见 [`text-engine-geometry.md`](../text-engine-geometry.md)（中文翻译见 [`text-engine-geometry.zh-CN.md`](../text-engine-geometry.zh-CN.md)），结构化文档规范见 [`document-engine.md`](../document-engine.md)。本文只拥有 browser implementation contracts、DOM lifecycle、input projection 和修改影响。

This directory owns Stanza's native browser projection of contracts from `../common/`. It may import `base/common`, `base/browser`, and editor common contracts. Neither `editor/common` nor `base` may import this layer.

Language presentation is an optional consumer of this layer and lives in `./view`, `./controller`, and feature-owned `../contrib/*/browser` directories. `ConfiguredCodeEditor` composes it through separate language-configuration and language-feature services; each contribution builds its model-level service from the relevant provider registry. The code editor widget and text model do not import language providers, grammars, diagnostics, or completion services.

Browser-owned responsibilities include:

- viewport observation and DOM virtualization;
- EditContext (native/textarea), keyboard, pointer, and composition-event adapters;
- font and glyph measurement;
- WebGPU device, DPR, glyph-atlas, and eligible visible-line rendering;
- DOM selection, focus, scrolling, and pointer projection;
- ARIA and screen-reader surfaces;
- presentation of editor-owned decorations and semantic tokens.

Glyph-margin features contribute model decorations only. `EditorGlyphMarginWidgets` owns stable button DOM, semantic product-icon mounting, ARIA state, lane geometry, and pointer target metadata. Folding and Debug own their decoration collections and controllers; neither provider creates browser elements or SVG markup.

`EditorTextAreaInputContext` provides the textarea implementation and `BrowserEditContext` provides the browser `EditContext` implementation when available. Both satisfy one `EditorInputContext` contract and own their concrete DOM, focus/ARIA state, composition lifecycle, screen-reader support, and platform-event routing into `EditorViewInputController`. The native implementation keeps the browser edit buffer synchronized with the common model and never creates a second document authority.

Pure text, history, selection, decoration identity, composition transaction semantics, and DOM-independent layout math remain in `editor/common`. Workbench parts may host the browser editor and own its external box, but must not reach through its component internals. Visual rules follow [`docs/ui-styling-ownership.md`](../../../../../docs/ui-styling-ownership.md).

Browser implementation follows the frontend-wide [`coding-guidelines.instructions.md`](../../../../../.github/instructions/coding-guidelines.instructions.md), editor-scoped [`editor.instructions.md`](../../../../../.github/instructions/editor.instructions.md), and browser UI [`browser-ui.instructions.md`](../../../../../.github/instructions/browser-ui.instructions.md).

The structured Document Engine is a sibling domain inside Stanza. Line-editor contracts must not import or expose document node, schema, profile, or transaction types.

## Current implementation

`EditorInputContext` is the browser input boundary. The native implementation is
split by responsibility under `controller/editContext/native`: the core adapter
owns the browser `EditContext` event bridge, `nativeEditContextUtils` owns focus,
bounded-window, and offset helpers, `nativeEditContextRegistry` exposes active
contexts to host integrations, the native factory owns capability detection,
and the native CSS owns the hidden editing surface. `EditorScreenReaderSupport` and
its simple/rich content projections provide the optional screen-reader mirror;
the rich projection reuses the viewport's semantic-token and bracket boundaries
without changing the mirrored source text. Both projections use bounded,
line-oriented accessibility pages, preserve model-to-DOM UTF-16 mappings across
page separators, and follow the viewport cursor/scroll geometry. `screenReaderUtils`
owns the page windows and DOM/model coordinate mapping. `BrowserEditContext`
keeps the browser edit buffer synchronized with the common model and never
creates a second document authority. When the API is unavailable,
`EditorTextAreaInputContext` provides the textarea implementation. Each concrete edit
context owns its focus and ARIA state, `CompositionController`, and screen-reader
support; `EditorView` selects one implementation and exposes that contract, while
`EditorViewInputController` owns semantic command routing independently of the concrete DOM element.

`CodeEditorWidget` is the canonical browser editing surface consumed by editor hosts and embedded widgets. It owns one `View` renderer and one `EditorView` input/controller owner; `browser/view.ts` and `browser/editorView.ts` keep those responsibilities separate. Its caller retains the shared `TextModel` and the editor-local `CursorsController`, so disposing a widget never disposes document state and multiple editors may safely use the same model. `WidgetContributionCollection` is the single owner of eager, interaction, render, idle, and lazy contribution instantiation. `ConfiguredCodeEditor` establishes language, typed capabilities, and editor-local before-save hooks around this surface; it observes but never owns the caller's model or persistence reference. `browser/editorBrowser.ts` remains the canonical owner of content-widget, overlay-widget, view-zone, and accessibility contracts. Independently selected contributions add folding, diagnostics, commands, clipboard, Suggest, placeholder, and text-drop behavior. `RichTextEditorWidget` is the sibling structured-document surface and owns structured selection, rich clipboard, and node-view lifecycle. `EditorDom` owns stable browser roots and their shared layout writes. Workbench owns model references, dirty/conflict state, save/revert routing, and persistence. Product widgets must consume the concrete browser widgets rather than assembling viewport and input internals themselves. `CodeEditorWidget` exposes only a registration seam for optional placeholder composition, while viewport padding is canonical editor geometry shared by row rendering, hit testing, scrolling, and placeholder placement.

`View` is the first native browser projection. It consumes `EditorViewportLayoutManager`, creates one component-owned scroll surface, and renders only the overscanned line range. Overlapping lines retain their DOM identity while scrolling. A new model version updates visible row text synchronously, and a shrinking document clamps both the common viewport state and native DOM scroll coordinates.

`View` is also the current view scheduler. `browser/viewParts` follows the VS Code view-part ownership map: `EditorViewLines` owns virtual text rows and semantic text projection; `EditorMargin`, `EditorGlyphMarginWidgets`, `EditorLineNumbersOverlay`, `EditorLinesDecorationsOverlay`, `EditorMarginLineDecorationsOverlay`, and `EditorBlockDecorations` own their respective margin and decoration projections; `EditorCurrentLineHighlightOverlay`, `EditorSelectionsOverlay`, and `EditorViewCursors` own active-line, selection, caret, and tracked IME presentation; `EditorViewZones` owns caller-provided DOM in reserved vertical space. `EditorViewportScrollbar`, `EditorMinimap`, `EditorDecorationsOverviewRuler`, and `EditorScrollDecorationViewPart` own scroll and overview presentation. `EditorDecorationsOverlay` owns decoration contracts, snapshots, visible-line indexing, inline projection, glyph-margin lookup, and marker aggregation, while `EditorIndentGuidesOverlay` owns indentation guides. Each concrete view part keeps its projection in its canonical file; `EditorViewPartCollection` dispatches one synchronous render pass with the immutable `EditorViewportLayout`.

The browser configuration seam is intentionally small. `editorConfiguration.ts` resolves the font and line-height values that affect initial geometry, `domFontInfo.ts` applies the same font vocabulary to viewport and diff roots, `elementSizeObserver.ts` coalesces initial and `ResizeObserver` dimensions, `tabFocus.ts` owns host-injectable Tab-focus state, and `fontMeasurements.ts`/`charWidthReader.ts` own font-environment reads. The `toggleTabFocusMode` contribution consumes that state for keybindings, DOM state, and announcements. `migrateOptions.ts` is the single compatibility boundary for the legacy option spellings that the public editor constructor still accepts; callers and view parts consume only the normalized options.

Standalone language-feature registration follows the public `(LanguageSelector, provider)` boundary. `standaloneLanguages.ts` translates the selector once into the internal provider registry's ownership metadata; feature providers do not carry `languageIds` as part of their public contract.

`createStanzaDecorationSource` may attach `linesDecoration` and `blockDecoration` details to a resolved snapshot. The line projection follows logical lines rather than wrapped fragments, while the block projection maps a range to the first and last visible visual rows and supports VS Code-style after-end, collapse, and four-side padding semantics. These details stay separate from the closed inline `DecorationPresentation` vocabulary, so diff and diagnostic owners can opt into the appropriate visual lane without teaching `View` about feature-specific classes.

`EditorDiffWidget` is a separate read-only review surface rather than two independently scrolling editor instances. Its caller owns a `DiffModel`, which observes caller-owned original and modified `TextModel` values and accepts only results pinned to their current versions. Workbench `IDiffService` creates `AppServerDiffComputationService` instances that adapt bounded diff results, hunk ranges, and grapheme-safe inline ranges to the editor's UTF-16 model; the Editor browser layer imports neither the transport API nor that adapter. The widget owns one virtualized scroll surface and side-by-side DOM rows, but owns neither text nor computation. Editing, selection history, syntax processing, and model persistence stay with ordinary editor parts. `nextChange`/`previousChange` and F7/Shift+F7 wrap over changed rows, add the component-owned `.active` state, and announce the original/modified location through the diff view's live region. Workbench `DiffEditorInput` gives the Workbench one synthetic tab resource while retaining two ordinary caller-owned text-resource inputs. `DiffEditorPane` acquires and releases both `TextModelReference` values, then hosts this view; it neither turns the synthetic URI into a text model nor owns either model's save/revert lifecycle.

`EditorMultiDiffWidget` composes an ordered collection of caller-owned `DiffModel` values in one virtualized outer scroll surface and reuses the same diff-row projection without importing Workbench. Workbench `MultiDiffEditorInput` owns the synthetic tab identity and ordered comparison list, while `MultiDiffEditorPane` acquires every underlying `TextModelReference`, owns their per-comparison `DiffModel` lifetime, and releases the complete session together. Product consumers such as SCM provide immutable comparison snapshots and open the Workbench input; they do not own widget internals or create a second text model authority.

Document views also own an optional minimap overlay configured through `IEditorMinimapOptions`. `EditorMinimap` consumes the common `EditorLayoutInfoComputer` geometry, projects visual rows and semantic-token colors into one canvas with `MinimapCharRenderer`, and owns its diagnostic/diff marker layer, slider, and pointer navigation. Document views use the common proportional minimap size by default while embedded views default it off; callers can select `fill` or `fit` explicitly. The minimap reads the canonical model and visual projection but owns no text, selection, scroll, or language state.

Text-bearing virtual row roots use ordinary `top` positioning rather than permanent transform promotion. With `experimentalGpuAcceleration: "on"`, `browser/gpu/styledViewGpuContext.ts` owns the per-window WebGPU device request and per-view canvas/DPR/atlas lifecycle. `GPULifecycle` returns the shared `IReference<T>` lifecycle contract; `StyledGlyphRasterizer`, `StyledTextureAtlas`, `StyledTextureAtlasPage`, and the styled shelf/slab allocators own the current CSS-style glyph placement; `StyledFullFileRenderStrategy` and `StyledViewportRenderStrategy` select bounded document or visible-row vertex generation; and `StyledRectangleRenderer` owns the rectangle buffer and transparent frame clear before text is drawn. These styled classes use `HTMLCanvasElement` and resolved CSS values, so they deliberately do not occupy VS Code's `GlyphRasterizer` and `TextureAtlas*` names, whose contracts use theme token metadata, `OffscreenCanvas`, and platform services. `viewParts/viewLinesGpu/styledViewLinesGpu.ts` coordinates the current GPU modules, uploads glyph pages, and changes a row to GPU-painted only after a complete frame contains it. The retained virtual DOM continues to own layout, browser geometry, input, and accessibility. Right-to-left text, ligatures, unsupported token decorations, and overlong rows stay on the DOM painting path. `experimentalGpuAcceleration` is the only public GPU editor option; device initialization or loss remains internal GPU state and leaves retained DOM text visible.

`EditorMarginLineDecorationsOverlay` also projects diagnostic severity markers into the document minimap by reusing the existing decoration snapshot and overview-ruler aggregation. They carry only a closed named severity and proportional line span; minimap projection never retains diagnostic text, source text, or a syntax result. Arbitrary caller decoration markers and syntax-color minimaps remain outside this browser contract.

`EditorIndentGuidesOverlay` projects indentation guides only for visible first fragments of logical lines. `browser/viewParts/indentGuides/indentGuides.ts` identifies complete visual indentation units from leading tabs/spaces, while `TextMeasurer` places each guide in the same coordinate system as carets and selections. Continuation fragments never duplicate a guide, and scrolling does not retain offscreen source text.

`common/languages/LanguageBracketPairs` owns one model-wide structural bracket index shared by matching, navigation, editing, and nested colors. It consumes the current lexical/token context, invalidates when model tokens or language configuration change, and exposes only valid paired ranges to `BracketColorizationSource`; strings, comments, and unmatched brackets remain uncolored. The token renderer composes bracket level classes with existing semantic-token spans rather than making a second text DOM or mutating source content.

With `EditorLineWrapping.On`, the common `ViewModelLines` converts each logical line into measured grapheme-safe visual rows. The browser `DOMLineBreaksComputer` supplies only the font-dependent batch break calculation; its `ILineBreaksComputerContext` reads logical model lines, while the public `ICursorSimpleModel.getLineContent` reads visual rows. `ViewModelLines.createCoordinatesConverter()` uses that same version-bound mapping for model/view positions, ranges, hidden lines, and wrapped boundaries. The viewport virtualizes those rows directly: continuation rows keep a blank gutter, horizontal scroll is disabled, and text/semantic-token fragments, selection and decoration rectangles, composition anchors, pointer hit testing, reveal, vertical keyboard navigation, and column selection all use the same mapping. `TextModel` remains the only document authority; rebuilding rows never creates a shadow model or alters history.

Code folding is an editor contribution under `../contrib/folding/browser`, following VS Code's `editor/contrib/folding/browser` boundary. The common `ViewModelLines` accepts a feature-neutral `EditorLineVisibilitySource` and composes it with soft wrapping. The folding contribution owns range data, fold state, hidden-line derivation, commands, and folding presentation styles. `EditorFoldingModel` owns tracked physical-line fold regions. Stanza merges registered language-provider ranges, synchronous lexical ranges for `{}`, `[]`, cross-line block comments and named regions, and indentation-derived ranges; Workbench registers App Server parser folds through the same provider registry instead of exposing parser state as an editor capability. The deterministic merge keeps only nested or disjoint spans. User-created manual ranges persist through provider refreshes, while a refresh replaces only provider-owned ranges and never takes ownership of fold state. `EditorHiddenRangeModel` derives hidden physical lines from collapsed regions; the common view-model line collection filters wrapped rows and retains a header-row anchor for temporarily hidden selections. `EditorFoldingController` maps Ctrl+Shift+`[` / `]` on Windows and Linux and Cmd+Option+`[` / `]` on macOS, while gutter controls use the same model. A collapse relocates active cursors hidden by that range to its header, before the viewport is reprojected. Ctrl/Cmd+K then Ctrl/Cmd+0 collapses all current regions; Ctrl/Cmd+K then Ctrl/Cmd+J expands them all; `[` / `]` recursively collapse/expand the innermost containing hierarchy; `1`–`9` select a fold level; `,` / `.` create/remove a manual range.

`TextDropController` accepts external `text/plain`, safe text reduced from `text/html`, and one bounded textual file. It inserts at the viewport's grapheme-safe hit target as one ordinary editor transaction. Paste behavior is not part of this contribution; non-text drops remain available to the hosting workbench.

`EditorInput.readOnly` flows into `CursorsController` rather than being treated as a textarea-only styling flag. The controller rejects every document command, undo/redo, and composition entry, so all browser adapters that submit through it retain selection/navigation/copy behavior without a path that can mutate the shared model.

`EditorViewLines` creates one text-only virtual row through `EditorViewLine`. `EditorViewLineOptions` is the shared DOM/GPU line configuration snapshot; `EditorViewLine` owns text rendering and per-line geometry, `CharacterMapping` maps UTF-16 columns to rendered spans, `RangeUtil` normalizes browser ranges, and `DomReadingContext` caches their layout basis. `ViewLayer` supplies the same visible-row reconciliation to line numbers, diagnostics, indentation guides, decorations, selections, and carets while each concrete view part owns its root and row DOM. Gutter width is derived from the current line-count digit width and participates in authoritative horizontal content measurement. `EditorSelectionsOverlay` and `EditorViewCursors` read one optional `CursorsController`; the controller remains caller-owned and is the only selection/cursor state owner.

`EditorContentWidgets` owns document-positioned widget DOM, measurement, preferred above/below/exact placement, secondary anchors, focus-preserving offscreen layout, and the separate editor-overflow root. `editorBrowser.ts` owns the public content-widget contract, while `View` and `CodeEditorWidget` expose add/layout/remove operations without taking ownership of caller-created widget state. `ViewOverlayWidgets` owns viewport-positioned widget DOM, and `EditorWhitespaceOverlay` owns whitespace glyph rendering. GPU-only ruler rectangles and the GPU debug marker remain in their corresponding `rulersGpu` and `gpuMark` parts.

`createStanzaDecorationSource` adapts one caller-owned `TextDecorationCollection<TMetadata>` without interpreting metadata in common code. Its resolver explicitly maps each snapshot to `search-match`, `error-underline`, `warning-underline`, or no browser presentation. The viewport observes any number of these sources and projects only their visible rectangles into a decoration layer below text and selection. It owns the event registrations, not the sources or collections. Resolved source snapshots are cached until the corresponding collection event, so scrolling does not rerun caller metadata resolvers.

`LanguageDiagnosticDecorationBridge` converts one current-version diagnostic store into a caller-owned generic decoration collection. `createStanzaLanguageDiagnosticSource` then maps every normalized severity to a component-owned underline. Error and Warning use their severity tokens; Information uses the focus token and Hint uses a dotted description-token underline. The projection retains an optional native tooltip with diagnostic source, code, and message. On the first visible row of each logical line, the viewport also renders the line's highest-severity diagnostic as a gutter marker. `DiagnosticHoverController` turns its current joined messages into a component-owned, non-modal rich hover and closes it on scroll. The viewport owns neither bridge, collection, store, nor model.

`DiagnosticNavigationController` uses F8 and Shift+F8 to select and reveal the next or previous current-version diagnostic, wrapping at either end. Every move also announces the selected severity, source/code when present, and message through the viewport live region.

`createStanzaSemanticTokenSource` adapts one caller-owned `LanguageTokenLineIndex` to Stanza's closed browser presentation vocabulary. Unknown worker token types are omitted by default; custom language resolvers may inspect token modifiers but must still return a named Stanza presentation, never an arbitrary CSS class. `getLineTokens` resolves one indexed line on demand. The viewport resolves only its target virtual range before replacing any row, so offscreen lines do not invoke the resolver and a resolver failure cannot partially update the visible window.

`projectStanzaSemanticTokenLine` validates each line snapshot before mutation, then creates text nodes and component-owned spans without parsing HTML. Joined DOM text must equal the model line exactly. Same-version token replacement rerenders visible line content without rebuilding rows; model invalidation removes stale spans before the normal model-version projection. The viewport owns only its event registration, not the source, common index, result store, or model. Semantic foregrounds come from registered `editor.token.*Foreground` theme colors owned by editor presentation. Legacy `editor.semanticToken.*Foreground` overrides are normalized only at the user-theme boundary.

`CompletionWidget` projects one caller-owned `LanguageCompletionSessionController` below the viewport's measured trigger position. It creates only component-owned listbox/option DOM, maps completion kinds through a closed text vocabulary, and projects `.visible` and `.focused`. Active-descendant ARIA state goes through `EditorView.setAriaOptions` to the selected edit context instead of mutating its DOM from the contribution. `EditorSuggestController` owns completion keydown and input interception. Mouse acceptance happens on mousedown so the synchronous focus rerender cannot detach the target before the edit is accepted.

The Suggest contribution creates one `LanguageCompletionService` and `LanguageCompletionSessionController` during editor configuration, then installs `EditorSuggestController` after `EditorView` exists. `EditorSuggestController` owns request cancellation, completion keyboard/input interception, and the `CompletionWidget`; Ctrl+Space sends an explicit Invoke request. Registered trigger characters send after the input transaction using the new version/caret; ordinary input refreshes an active incomplete result. Requests require one collapsed selection, and request errors do not undo a successful text edit. The session must observe the exact service-owned result store.

`EditorSuggestController` owns the browser widget but not the common session, service, registry, result store, selection controller, or model. Session disposal hides the widget; widget disposal clears its active descendant through the edit-context ARIA owner. Visual geometry and interaction state live in `../contrib/suggest/browser/media/completionWidget.css` and consume existing dialog, list-selection, foreground, border, and shadow theme tokens.

`EditorFindController` owns the per-session find/replace dialog and keyboard routing over `common/model/textModelSearch.ts` and `contrib/find/common/textSearchCommands.ts`. It projects matches through a caller-owned `TextDecorationCollection`; the viewport consumes that collection only through `SearchMatch`. Closing or disposing the controller clears this projection without changing the query or document. A non-empty selection at opening becomes a `NeverGrowsAtEdges` tracked scope. The Find in Selection control and Alt+L reuse that scope for both navigation and replace-all after match navigation has changed the editor selection. `media/findWidget.css` owns the dialog geometry and its `.visible` and `.checked` interaction states, while ARIA attributes expose the equivalent accessible state.

`GotoLineController` owns Stanza's Ctrl+G (Command+G on macOS) line/column dialog. Its common parser supports one-based `line[:column]`, backward negative values, and `::` UTF-16 offsets; while the dialog is open it previews by revealing the parsed position without mutating selections. Enter commits one collapsed primary selection, while Escape restores the pre-dialog scroll position. Its geometry and interaction states are owned by `media/gotoLineWidget.css`.

`LineCommentController` consumes Ctrl/Cmd+`/` only when the resolved language configuration has a line-comment token. It delegates all mutation, selection mapping, and undo grouping to `common/lineCommentCommands.ts`; the browser adapter only handles the key event and reveal. Unsupported languages keep the shortcut available to other browser or workbench handlers.

`BlockCommentController` maps Shift+Alt+A to the configured block-comment pair. Its common command handles range wrapping, pair removal, collapsed cursor placement, selection mapping, and undo; the browser adapter only filters the platform chord and reveals the resulting primary cursor.

`LineOperationsController` under `../contrib/linesOperations/browser` handles Ctrl/Cmd+Enter, Ctrl/Cmd+Shift+Enter, Ctrl/Cmd+Shift+K, Shift+Alt+ArrowUp/ArrowDown, and Alt+ArrowUp/ArrowDown without browser-native text mutation. Its line-operation commands insert, delete, duplicate, or move the union of selected physical lines in one selection-aware transaction, then the adapter reveals the resulting primary cursor.

`LineJoinController` maps Ctrl+J (Command+J on macOS) to `common/lineJoin.ts`. The common command reduces overlapping cursor/range targets before replacing whole physical-line spans, removes following indentation, retains a single separator when neighboring fragments contain text, and keeps the resulting selections in one isolated undo transaction. The browser adapter owns only chord filtering and reveal.

`TransposeController` maps VS Code's macOS Ctrl+T chord to `contrib/transpose/common/transposeCharactersCommand.ts`. It swaps complete graphemes rather than UTF-16 code units, supports a line break at a physical-line start, excludes range selections, and resolves overlapping multi-cursor edits before the one isolated transaction.

`WordWrapController` maps Alt+Z to a viewport-local word-wrap toggle. `View` always virtualizes through its visual-line source, so switching wrapping rebuilds row geometry, scroll limits, hit testing, selection projection, and rendering without changing the model or re-creating the editor. The `.word-wrapped` root class reflects that component-owned presentation state.

`OccurrenceSelectionController` handles Ctrl/Cmd+D and Ctrl/Cmd+Shift+L without browser-native selection logic. The common selector resolves one Unicode-safe source word for a collapsed primary cursor, then adds the next exact match or replaces the set with every exact match; the adapter only updates and reveals the live selections.

`WordHighlighterContribution` asks the first matching language document-highlight provider, falls back to `TextualDocumentHighlightProvider`, cancels stale requests, and applies read, write, or textual decorations after `occurrencesHighlightDelay`. `occurrencesHighlight` selects off, current-document, or all open editors sharing one language service; F7 and Shift+F7 move through the current ordered highlights without starting another request.

`EditorSelectionHighlighter` belongs to the multicursor contribution and handles only non-empty selections. It finds exact textual matches, excludes every active selection, rejects whitespace and disallowed multiline or over-limit text, and uses whole-word matching when the selected range is one configured language word.

`MultiCursorController` adds one logical-line caret above or below every existing active cursor. Chords follow Windows (Ctrl+Alt), macOS (Cmd+Alt), and Linux's non-conflicting VS Code secondary binding (Ctrl+Shift+Alt); the common command clamps columns and rejects duplicate or overlapping new carets. Shift+Alt+I replaces non-empty selected rows with their VS Code-compatible line-end carets through the same DOM-free common command. Those actions and occurrence-selection changes record a bounded cursor-only history; `CursorUndoController` restores it with Ctrl+U on Windows/Linux or Cmd+U on macOS without changing the document's undo stack.

`BracketMatchController` is a presentation adapter over the common `LanguageBracketPairs` index. According to `editor.matchBrackets`, it projects the current exact or enclosing collapsed-cursor pair as two `BracketMatch` decorations, reuses the viewport's normal virtual-row geometry, and owns neither the model, selection controller, index, nor decoration collection.

`BracketNavigationController` maps Ctrl/Cmd+Shift+`\\` through the same borrowed `LanguageBracketPairs`, so a go-to-bracket gesture has identical string/comment filtering to bracket highlighting. It owns only the chord, live selection update, and reveal; structural indexing remains common language state.

`BracketEditingController` maps Ctrl/Cmd+Alt+Backspace to an isolated common transaction that removes distinct valid bracket tokens. It never mutates the browser input surface directly and only consumes the chord if a bracket pair can be removed.

`browser/services/editorWorkerService.ts` owns the model-bound `VersionedEditorWorkerClient`; `EditorBrowserWorkerFactories` only composes module Worker transports. The first request sends a full immutable snapshot, later commits update the Worker mirror, and current requests reuse that version without copying the document. `EditorWorkerRequestExecutor` owns Unicode scanning, formatting-edit reduction, and numeric or well-known textual value navigation. Each browser factory result owns one Platform `BrowserWorkerClientPort`, which removes listeners and terminates its Worker on disposal. Direct `ConfiguredCodeEditor` callers use the same client with an in-process executor; browser hosts and Standalone install the module Worker factory. All dedicated workers enter through `editor.worker.start.ts` and its single `start()` lifecycle.

The wire carries only versioned plain DTOs. Completion positions and ranges are reconstructed as realm-local common values before result application. Cancellation posts a cancel envelope, Worker errors poison the client so the coordinator can replace it, and the Platform port owns browser event listeners and Worker disposal without owning language state.

Protocol v4 retains the document-mirror contract: one full snapshot initializes the Worker Piece Tree. Subsequent model commits send ordered offset/length/text deltas, and requests reference the mirrored version without copying document text. A version gap falls back to full initialization; an invalid remote sync clears the mirror and poisons the client. Immutable Piece Tree snapshots keep cancelled old-version provider work isolated from later synchronization.

Protocol v4 additionally carries the client-confirmed per-lane result request ID. Syntax responses may use validated ordered item splices with independent line shifts; completion remains a full result codec. Result delta state belongs to the common wire client/server, not the browser port adapters.

The Worker also publishes its actual provider registry through a separate completion-catalog side channel. The browser client waits for the first validated revision, observes later registration/removal revisions, and exposes only immutable metadata to `LanguageCompletionService`. Custom Workers are prewarmed so the first typed trigger can wait for this handshake. Failure clears the old catalog; the next trigger rebuilds the Worker and waits for its new catalog instead of routing through stale renderer metadata.

A second completion-specific side-channel publishes named provider modules and accepts Active/Inactive requests. It never attempts to clone provider functions. Worker-local loading and atomic registration complete before the activation response, while the ordered port delivers the corresponding provider-catalog revision before the browser releases its first-request readiness barrier.

Deferred completion details use a third completion-specific side-channel. `resolveData` never enters browser state: the renderer sends only the list request/model/provider/item identity and receives normalized detail and documentation text. Focus changes abort the prior request. The selected option projects `.resolving` with `aria-busy`, then renders resolved documentation through text nodes; resolve failure leaves the candidate list and acceptance identity intact.

`EditorBrowserWorkerFactories` exposes general editor, syntax, and completion factories for the standalone runtime. Their clients use the Platform-owned `BrowserWorkerClientPort`, and every Worker realm enters through its dedicated common Worker main; general computations, syntax providers, and completion providers stay in independent failure domains. The syntax entry publishes `language.lexical`, owns its Worker-local language configuration registry, and updates the shared versioned line cache after each mirror sync before serving ordered token and diagnostic requests. `SyntaxModuleWorkerClient` waits for catalog publication and successful module activation before sending the first request. The Editor core owns registries, generic providers, request coordination, model mirrors, result codecs, and result application, but it does not install concrete language descriptions, editing configurations, or App Server adapters. Workbench and Standalone compose those registrations at their own startup boundaries. Workbench additionally owns parser provider registration, the TextMate grammar catalog, theme data, TextMate Worker creation, and catalog-change scheduling through `ITextMateService`.

Selection and decoration projection share `createStanzaRangeRectangles`, so end-exclusive ranges, selected line breaks, prefix measurement, and render-line clipping have one implementation. Presentation sources are resolved before the existing decoration DOM is reset; an invalid presentation therefore fails without partially replacing the current decoration layer.

`View.getTargetAtClientPoint` converts a PointerEvent-compatible client point into one immutable Stanza geometry target without changing selection. `SemanticMouseTargetFactory` adds browser semantic areas such as line numbers, feature gutters, widgets, scrollbars, and view zones while preserving the common `Gutter`, `Text`, `EmptyContent`, and `AfterLines` distinctions. The browser bounds establish viewport coordinates; fixed line height and current scroll state establish the line, while sticky gutter geometry remains independent of horizontal scroll.

`hitTestStanzaEditorPoint` resolves horizontal text positions at adjacent caret midpoints. It uses grapheme boundaries when `Intl.Segmenter` is available and falls back to Unicode code points, so emoji and combining sequences are not split into arbitrary UTF-16 interiors. Prefix widths use the same `TextMeasurer` as rendering, including tab stops and shaped text. The grapheme implementation is owned by `editor/common/textSegmentation` and is also consumed by keyboard navigation; browser code does not define a second Unicode boundary policy.

`EditorPointerSelectionHandler` is the first browser input policy layered on that query. Primary-button clicks place one caret, Shift-click extends the existing primary anchor, character drags preserve anchor/active direction, and gutter drags select complete lines including their line breaks. Gutter Shift-click extends the existing anchor to the selected line boundary. Browser double-click detail selects and drags complete segments from `wordSelection.ts`; triple-click detail selects and drags complete lines. Shift-double/triple click preserves the prior primary anchor. For a context-menu gesture, a hit inside an existing non-empty selection keeps that selection; another hit replaces it with one caret. The controller leaves menu composition and display to its host.

Alt+Shift primary drag is the explicit column-selection gesture. It converts the anchor and target through `View.coordinatesConverter`, asks `ColumnSelection.columnSelect` to operate on `View.cursorModel` with `CursorConfiguration` visible columns, then converts each returned visual state back to a model selection. Wrapped rows therefore participate independently, direction follows the drag, and short rows collapse at their real end without synthetic trailing whitespace. The gesture is distinct from the configured additive multi-cursor modifier, which never consumes Shift.

`MouseHandlerOptions.multiCursorModifier` selects exact `Alt` gestures by default or `ControlOrMeta` gestures explicitly. The selected modifier without Shift preserves existing selections and adds the active character, word, or whole-line result as primary. `editor/common/cursor/cursorMoveCommands.ts` owns toggle removal, last-selection retention, deduplication, overlap replacement, and primary-index mapping. Shift keeps its ordinary extension meaning.

`PointerEventRouter` owns viewport/window-level pointer dispatch, disposable drag sessions, and browser pointer capture. `EditorPointerSelectionHandler` owns gesture policy and maps semantic hit targets to selection state. Its anchor is a temporary collapsed position or complete word tracked range, so synchronous model edits during a drag cannot leave a stale position or semantic range. An additive gesture also tracks the original selections temporarily, preserving their order, direction, and primary identity across the same model edits. Pointer completion, cancellation, window blur, disposal, and failed setup all release capture and the tracked anchor. The viewport, pointer adapter, and selection controller reject wiring across different `TextModel` instances.

`View.getNearestTargetAtClientPoint` clamps an active drag to the nearest viewport edge without weakening strict `getTargetAtClientPoint` queries. `BidirectionalDragScrolling` maps overflow distance on each axis to a bounded pixels-per-second velocity and uses `base/browser/AnimationFrameScheduler` to advance the Viewport. Each frame repeats nearest-edge targeting, so the active character, word, whole-line, or Shift selection policy continues unchanged. Re-entry, scroll limits, completion, cancellation, blur, disposal, and replacement by another drag stop its scheduled work. The explicit bidirectional name avoids occupying VS Code's abstract `DragScrolling` owner, whose top/bottom and left/right operations have separate lifecycles.

`KeyboardNavigationController` maps local keydown events into common character, word, line, page, and document navigation commands. It uses explicit Windows/Linux or macOS routing, preserves Shift extension and multi-selection, retains preferred columns across vertical movement, and ignores composing, AltGraph, unknown, or already-handled events. Page distance comes from the current fixed-line-height layout. `View.revealPosition` then uses measured line prefixes and line geometry to reveal the primary active position horizontally and vertically. The controller deliberately does not own text insertion, deletion, clipboard, or composition DOM events.

`EditorView` is the browser composition root: it creates `EditorViewInputController`, selects one `EditorInputContext` implementation, and exposes the selected context's focus, ARIA, screen-reader, composition, and input contracts. The edit context owns its concrete DOM, `CompositionController`, accessibility support, and browser-event routing; `EditorViewInputController` executes semantic commands, while `EditorSuggestController` owns completion policy. The view projects focus with `.input-focused`, requires the same `TextModel` as the viewport and selection controller, and releases only what it owns.

Insert toggles the instance-local `.overtype` state. In that mode ordinary single-line input replaces following graphemes without crossing a physical line break; selected text and multiline input retain ordinary replacement behavior. Configured bracket pairs and IME composition keep their dedicated input paths.

Language-aware typing is supplied by the browser input layer through `EditorLanguageEditingAdapter`; it is independent of optional bracket presentation. The adapter owns one `common/cursor/LanguageAutoClosingTracker` for its editor instance and records only actions whose expected model version committed. Opening tokens route through common cursor auto-close or selection-surround commands. A matching closer is overtyped without a model transaction, and Backspace removes both sides of an empty pair, only when that tracker confirms the closer came from the editor's auto-close transaction. Matching user-authored text retains ordinary typing and Backspace semantics. The configuration is resolved on each edit event, so priority changes take effect without rebuilding DOM. Pair policy, tracked provenance, multi-selection mapping, and history modes stay in `editor/common/cursor`.

The same adapter routes `insertLineBreak` and `insertParagraph` through `createLanguageEnterCommand`. Its explicit indentation options select tabs or spaces plus tab size for this editor instance and are owned by the language-editing contribution rather than `EditorView`. Enter rules are fetched on every event, so contribution priority and disposal take effect immediately. The indentation contribution owns editor indentation policy; the language contribution owns rule matching.

The session also derives folding from the same resolved configuration. Structural brackets and multi-line comments remain lexical folds; `foldingMarkers` adds language-owned named regions. Stanza's built-ins recognize `// #region` and `// #endregion` for ECMAScript, JSONC, and Rust. Marker patterns are common configuration, so browser code only projects and toggles the resulting folding model; a contribution must include its comment delimiter to avoid treating ordinary source text as a region.

`coreCommands.ts` registers editor-wide commands such as Select All through `editorExtensions.ts`. `LineSelectionController` owns repeated physical-line selection, while `LineOperationsController` under `../contrib/linesOperations/browser` owns selected-line Tab and Shift+Tab routing. The corresponding transformations remain DOM-free in their feature modules, deduplicate physical lines across selections, map directional selection endpoints through the transaction, and consume the language-editing contribution's indentation policy. Collapsed Tab remains ordinary text input. Word-deletion `beforeinput` types route through `common/cursor/selectionSetWordOperations.ts`; the upstream-shape word movement and deletion ranges remain in `cursorWordOperations.ts`. Ctrl/Cmd+L expands each selection through one more physical line using the DOM-free `../contrib/lineSelection/browser/lineSelection.ts` model; repeated use includes each non-final line break and retains the primary selection identity.

`language.lexicalContext` may inject a caller-owned synchronous context source for the same model/language. Without one, the controller owns a `LanguageLexicalContextIndex` that lazily scans through the requested line and invalidates changed suffixes. Enter uses structurally filtered slices, and pair typing uses token identity for auto-closing `notIn`; neither command imports browser or Worker state.

`ClipboardController` owns copy, cut, and paste semantics: selection extraction, whole-line policy, metadata, line-ending conversion, safe syntax HTML, URI-list paste, and bounded text-file paste. Matching metadata distributes one text per target selection; external text or invalid metadata repeats plain text at every selection. `editContext/clipboardUtils.ts` only adapts browser event transfers and reduces external HTML to inert text. Generic cursor deletion receives the already-decided cut ranges and has no clipboard dependency.

`TextDropController` owns text and bounded text-file drops only. `ClipboardController` owns bounded text-file paste and non-comment `text/uri-list` paste. A file must have a plausibly textual MIME type or known text extension and remain within 5 MiB; neither path opens an arbitrary local path. An asynchronous paste must still match the captured model revision and complete selection set, while a drop must still match its captured revision.

When an event exposes no usable text or metadata, `ClipboardController` asks platform `IClipboardService` for plain text. Browser and Electron implementations only adapt system text reads and writes; editor metadata and HTML never enter the platform contract. Permission denial, an empty result, or a stale result leaves the model unchanged. If a copy or cut event lacks writable event data, the same service writes plain text; cut waits for that write to succeed before editing the model.

Cut and paste are rejected while `CompositionController` owns a protected IME transaction; copy remains available. This prevents a browser clipboard event from invalidating or interleaving the provisional composition revision.

Empty-selection behavior is an explicit `Line` (default) or `Ignore` policy. Line mode copies complete lines with LF ownership, merges duplicate/overlapping cut ranges, and writes version 2 metadata. A matching all-line paste inserts at target line starts while preserving columns; multiple carets on one target line become one ordered insertion. Mixed modes or non-empty targets fall back to ordinary per-selection paste. Plain line entries concatenate without introducing extra blank separators.

`CompositionController` maps either edit-context composition stream to one protected common session. The context supplies normalized provisional text and relative selection; the controller owns cancellation, commit, external invalidation, `.composing`/`.ime-input` presentation, and caret positioning. Escape, blur, disposal, and `IME.disable()` cancel; end commits. Neither native nor textarea input is allowed to create a second model or history implementation.

The common session exposes its active `currentRange`; `EditorViewCursors` owns a temporary tracked copy and projects its underline through the same range geometry used by selections and decorations. It is cleared on commit, cancellation, external invalidation, IME disable, and disposal. Empty active end commits deletion, while an end arriving after the session closed is ignored.

The component reuses `base/browser/dom` for disposable events and DOM reset, `base/browser/geometry` for host measurement, and `base/common/lifecycle` for ownership. Its `.stanza-editor` root is styled by `widget/codeEditor/editor.css`, while internal line classes stay with their owning `viewParts/*/*.css` files; Workbench hosts may size the root and explicitly select `focusOutlineOwner: "host"` when their direct control owns one surrounding focus indicator, but must not override internal rows or focus state. The component projects stable `.active` state for the primary active line and `.primary` identity on the primary caret; CSS does not use ARIA attributes as visual selectors. Embedded presentations omit `.active` by default. Vertical padding participates in the viewport content height and row coordinates instead of being simulated by a host selector; left and right padding are component-owned text-measurement inputs, so wrapping, carets, placeholders, and pointer hits share one inset.

`DomTextMeasurer` derives the active font, letter spacing, tab size, and horizontal padding from the line layer's computed style. Canvas measures shaped segments and fallback glyphs; tabs advance to measured space-based tab stops. `TextMeasurer` is the small injectable contract used by tests and future specialized font engines.

`LineWidthIndex` takes one bounded synchronous first slice when the view is constructed, then schedules remaining non-wrapped lines through cancellable idle slices. Its current maximum is a lower bound until completion, never a claim about unmeasured lines. An edit cancels a pending generation and starts again from the current model version. After completion, transactions group edits by affected old line ranges, measure only their new line groups, and update a counted width set. Font refreshes restart this same policy because every cached width may have changed. Browser font-loading completion and explicit `refreshFontMetrics()` both trigger it.

The current renderer is fixed-line-height and mutates text only through the selected EditContext adapter, never through contenteditable DOM. Its resolved font size is explicit even when the host omits one, and font zoom scales that resolved pixel value instead of replacing it with an inherited `em` size. Focused carets blink through component-owned CSS when motion is allowed and remain visible when the user requests reduced motion. Canvas-unavailable runtimes use a font-size-derived fallback advance. For wrapped documents, `ViewModelLines` synchronously measures only a bounded first line slice, leaves later logical lines as one-row placeholders, and finishes their wrap measurement through cancellable idle slices before atomically publishing the complete projection. IME clause segmentation and mobile composition variants, semantic-token delta presentation beyond Stanza's closed modifier vocabulary, browser-driven wrapping, and empirical cross-platform screen-reader acceptance remain future work. Mixed-run BiDi asks `EditorViewLine` for browser `Range` rectangles and caret positions; its `CharacterMapping` selects the rendered child spans, `RangeUtil` reads their browser rectangles, and `DomReadingContext` supplies one cached coordinate basis for visible selection/caret, decorations, composition anchors, pointer hits, and vertical navigation. The textarea edit context provides the accessible IME/VoiceOver surface when the browser has no EditContext API, while the native implementation uses the browser editing surface; both share the explicit `dir` with the rendered line configuration. `SemanticTokenModifier` maps only standard declaration/readonly/static/deprecated/abstract/async names to component-owned classes; unknown provider strings are intentionally excluded from DOM projection. Syntax result deltas and relative token-line payload reuse are common-layer capabilities; this browser layer consumes only the current visible-line query and does not own their persistence policy. `EditorDecorationsOverlay` resolves only decorations whose logical-line range intersects the rendered window and rebuilds its interval index only when a source collection changes.
