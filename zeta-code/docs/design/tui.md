# TUI 架构

TUI 负责把对话呈现在终端里：接收输入、显示回复、切换会话和处理面板。App Server 负责执行任务、决定权限和保存数据。判断功能是否已经可用，先看[功能现状](../capabilities.md)。

## 一条消息怎样变成回复

1. 输入组件保存草稿，并根据当前任务状态决定发送方式：空闲时提交新任务；运行中 Enter 排队，Ctrl+Enter 补充当前任务。
2. Thread 模块把输入转换为类型化请求。请求在后台执行，界面继续接收按键。
3. App Server 执行任务，发送状态和正文更新。TUI 检查更新属于哪条对话，以及是否遗漏了中间事件。
4. 主事件循环把有效结果交给对应模块，更新界面状态。
5. 绘制代码读取这些状态，计算正文、输入框和面板的位置，再输出终端字符。

Session 是包含多条对话的会话；Thread 是其中一条对话；Turn 是一次任务执行。任务是否运行、结束或等待批准，由后端状态决定，不能从回复文字猜测。

## 产品边界

| 部分 | 负责什么 |
| --- | --- |
| CLI | 解析参数，选择工作目录和 profile，建立连接，处理重连与退出码 |
| TUI | 草稿、焦点、滚动、面板、终端绘制，以及用户操作到后端请求的转换 |
| App Server | 会话与任务状态、执行、权限、持久化、命令去重和订阅协议 |

TUI 通过 `zeta-app-server-client` 调用后端。即使连接在进程内，也要经过初始化、类型化请求和通知解码；不能直接调用 Core、存储、模型或工具执行模块。

本地只读文件补全可以使用 `zeta-file-search`。需要权限、跨进程一致性或版本检查的数据，必须经过负责该数据的后端接口。

## 功能放在哪个模块

一级目录按用户能力划分。一个文件足够时使用单文件；有独立状态、生命周期或依赖时才拆子目录。模块使用 `foo.rs` 与 `foo/`，不使用 `mod.rs`，也不为目录整齐创建空文件。

| 模块 | 主要工作 |
| --- | --- |
| `thread` | 当前对话的输入、排队、批准、提问、正文、滚动和分页 |
| `sessions` | 会话列表、预览、详情、创建、切换和归档 |
| `config`、`keymap`、`theme` | 各自的设置、编辑、校验和保存 |
| `skills`、`models`、`connectors`、`mcp`、`dirs` | 各自的目录、面板和操作请求 |
| `memory` | TUI 内存诊断的运行状态、句柄、开始、停止与有界段轮换；启用意图来自 Config |
| `status` | 状态行、当前对话信息和进程资源展示 |
| `app` | 启动、页面组装、事件路由、请求调度和退出 |
| `widgets`、`render` | 通用交互控件，以及文字测量、折行、高亮和颜色映射 |
| `terminal`、`client`、`host` | 终端资源、通信任务，以及剪贴板、导出和进程采样等系统操作 |

- 具体代码入口见[实现指南](../../tui/README.md#文件与职责)。
- 不要把一个功能的状态、请求和结果分别散落在 `features`、`components` 或 `app` 中；也不建立统一 Feature 接口、全局服务容器或任意回调总线。

通用控件只认识文字、条目标识、选择状态和动作，不能理解 Session、Skill 等产品概念。仅有“以后可能复用”不足以把控件移出功能模块。各能力可以提供窄的只读数据供其他能力使用，但不能互改内部状态或形成循环依赖。

## 状态由谁修改

所有可见状态由主事件循环更新。后台请求、文件搜索和剪贴板操作只返回结果；绘制代码只读取状态。

| 状态 | 更新依据 |
| --- | --- |
| 任务阶段、等待批准、Goal 和 Plan | 后端完整快照或有效通知 |
| 草稿、光标、选择、展开和滚动 | 当前组件接收到的用户操作 |
| 设置保存、导出等操作的结果 | 对应操作的完成事件 |

例如任务正在运行时，即使导出失败，Enter 仍应排队，Ctrl+C 仍应中断任务。局部操作的错误不能把当前任务改成空闲或失败。

Thread 收到完整快照时，应一起更新任务阶段、计划、等待交互和权限模式。当前 Thread 和当前 Turn 各有一个状态负责人，不能在事件循环和 App 中再保存一份需要手工同步的副本。

`AppDriver` 持有连接、订阅和后台任务；各功能模块解释自己的请求参数和完成结果。主循环只协调顺序，不能变成逐项实现所有功能的大型分支。

## 后台请求与旧结果

耗时操作在后台执行。中断和回答批准请求必须能及时送达，不能等普通查询完成。

| 请求 | 调度要求 |
| --- | --- |
| 中断、批准、回答和退出 | 独立的高优先级有界通道 |
| 发送消息、修改会话、保存设置 | 同一目标的写入保序，不同目标可以并发 |
| 刷新正文、目录和状态 | 可并发；仅接受当前请求版本的结果 |
| 文件、剪贴板、导出和浏览器操作 | 有界后台任务 |

异步结果必须带上目标身份，以及请求编号或代次。例如从对话 A 切到 B 后，A 的旧回复不能覆盖 B；搜索从 A 改成 B 再改回 A，第一次 A 的结果也不能冒充最新结果。

写请求遵守协议中的 `CommandId` 和预期版本。重试同一次写操作时保留原命令身份。退出或断线后取消或结束旧任务，不能只丢弃句柄让任务继续运行。

## 流式更新与重绘

状态变化与高频正文分开处理。批准、错误、写入结果、删除和清空等事件逐个保序处理；高频正文只在同一会话、对话和流中合并语义相同的完整新值。合并不能跨过提交、删除、清空或用户输入。

发现序号、正文版本或流式游标不连续时，清除不可信的临时正文并重新读取后端快照。流身份变化、连接代次变化或通道溢出同样需要重新同步；不能靠拼接文字补齐丢失的事实。

重绘只合并画面请求，不丢状态事件。连续输出共享第一次确定的绘制期限，后来的输出不能一直推迟它；用户输入可以提前触发绘制。持续输入也不能阻塞后端控制事件。

## 正文与终端历史

`thread/transcript` 管理一个有序的 `TranscriptCell` 集合，包括消息、执行结果、提示和错误。单元有稳定标识，流式更新和执行完成只修改内容，不改变其身份与位置。

- 当前[正文模型](../../tui/src/thread/transcript/model.rs)已区分 `ContentCell`、`LocalCommandCell` 和 `ExecCell`，绘制实现位于各自模块。
- 绘制接口要求见[正文绘制约定](../spec/transcript-rendering.md)；本次文档梳理尚未验证新实现是否逐项满足。

正文的测量、绘制和命中使用同一份派生结果。缓存必须包含内容版本、宽度、主题和其他真实失效条件，并设置上限。用户向上阅读后，用单元标识与单元内行偏移固定位置；新输出不能把读者推回底部。

同一份正文按首个实时单元分为两段：

- **已定稿前缀**：按顺序写入终端回滚区，一份内容只提交一次。
- **可变尾部**：继续在当前画面更新；普通跟随最新画面只绘制这一段。

进入正文浏览时再组合两段。终端写入历史时借用并恢复主屏幕顶行，不能把输入框、补全、面板和状态栏一起滚入历史。恢复旧会话会读取完整历史分页，再按从旧到新的顺序安装正文。

- Welcome 是正文前的产品页眉，不是后端消息。
- App 提供它的格子，正文模块把它纳入同一滚动位置。
- 输出样例见[正文输出](../spec/transcript.md#正文单元会输出什么)，终端验证范围见[兼容性记录](../../tui/README.md#终端历史兼容性验证)。

## 会话切换、预览与详情

切换会话或对话时，一起安装新的身份、订阅和完整快照。各 Thread 可以保留草稿、排队内容和阅读位置，但保存数量和缓存容量必须有上限。

会话预览读取打开时的快照，上翻时加载更早历史；它不订阅实时输出。关闭预览后回到原列表，保留当前项、分组展开状态、焦点和草稿。

会话详情通过 `session/read` 展示根对话、分支、委派关系、状态、等待原因和结果。打开期间每秒读取一次，同一时间只允许一个请求；目录变化可以提前刷新。关闭后停止读取，晚到结果按打开代次丢弃；刷新保留滚动位置，会话删除后关闭详情。

- 会话用量可以合计全部 Thread，上下文窗口仍属于单条 Thread。
- `/status` 的 Thread 页显示当前对话，Processes 页显示本机资源；不推测每个 Agent 分摊的 CPU 和内存。
- 用户可见统计口径见[状态规格](../spec/status.md)，后台实现见[采样设计](process-resources.md)。

## 输入区、布局与样式

`ChatPanel` 管理底部输入区：普通输入、命令面板、批准或提问在这里切换。它负责打开、关闭和转交输入；具体界面负责自己的按键、期望高度、绘制、命中和动作结果。

`TabList` 统一维护当前页签，并解释页签区获得焦点后的切页和进入正文按键。正文组件维护自己的字段或条目焦点，到达上边界时只报告结果；父面板负责在页签区与正文之间交接焦点和执行切页后的业务动作，不读取正文内部索引。嵌入另一个组件的正文时，未绘制的内部页签必须关闭，不能成为键盘可到达的焦点。

命令面板属于正常布局，可以按内容使用剩余高度，必要时让正文高度降为零。详情和补全才使用覆盖绘制。App 分配整页区域，各组件用同一份测量结果绘制和判断命中。

键盘和鼠标进入同一个组件动作。具体操作见[交互规格](../spec/interaction.md)，部位和尺寸见[布局规格](../spec/layout.md)，字符与颜色见[样式规格](../spec/styles.md)。

主题模块读取和校验文件，绘制模块只接收已经解析的颜色。计时变化通过事件推进；绘制时不能读取文件、发送请求、启动任务或修改订阅。

## 终端退出与连接恢复

终端模块负责原始输入模式、主屏幕、粘贴、焦点上报、鼠标捕获和挂起恢复。资源获取失败时逆序释放已经取得的部分；恢复操作可重复调用。新增终端模式必须同时补齐获取失败、正常退出和挂起恢复的测试。

TUI 接管一次已经初始化的连接。传输中断时只把持久化 Session/Thread 身份交回 CLI，由 CLI 决定重连；新连接重新读取后端状态，不重放旧连接里的待执行请求。服务端正常关闭或协议错误不能当成普通传输断线重试。

进程资源采样、导出和剪贴板属于 Host 操作，不能直接修改 App。资源读数只保留尚未处理的最新值；状态模块最多保存 301 个本机内存合计读数。

## 验证这些约定

测试放在行为所属模块，跨模块场景放在 App 或 CLI 集成测试。尤其检查：运行中局部操作失败、普通请求未完成时中断、切换后旧结果到达、断线后的任务清理、缓存上限、终端获取到一半失败，以及密集输入时控制事件仍能处理。

字符布局测试用于检查文字、折行、焦点和颜色；状态、请求、顺序、资源释放与文件副作用需要独立断言。执行命令见[测试与支持边界](../../tui/README.md#测试与支持边界)。
