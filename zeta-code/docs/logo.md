# Zeta Code Pet Sprite 与点击动作

> 状态：终端格格式、命名帧、动作时序、构建嵌入和预览已实现；Welcome 点击播放尚未实现。
>
> 本文拥有 `zeta code` Welcome 宠物的绘制格式、动作语义和验收规则。[界面部位词典](LAYOUT.md)拥有 Welcome 的页面位置与空间不足时的隐藏规则，[TUI 样式](styles.md)拥有一般颜色规则，[TUI crate README](../tui/README.md)记录当前实现入口。

## 结论

Pet 采用和 Claude Code 同一类的终端绘制方案：设计源直接写出每个终端格要使用的字符、前景色和背景色，运行时原样绘制，不再把高分辨率像素自动编码成 Unicode 八分块字符。

这三个属性共同决定一个格子的外观：

```text
字符：▛
前景色：身体蓝
背景色：黑
```

只保留轮廓相同的像素并不等价。换成互补字符、交换前景色和背景色，或者把带背景色的空格当作透明格跳过，都会受到终端字体字形、字符接缝和行高的影响。设计源因此保存最终绘制指令，而不是保存一张让编译器猜字符的像素图。

Pet 只有一个可编辑设计源：[`pet.sprite`](../tui/assets/welcome/pet.sprite)。每帧固定输出 `8×4` 个终端格，Welcome 固定预留 `8×5` 的 Pet 区域。

## 1. 文件格式

当前格式是 `version 2`：

```text
version 2
size 8 4
color B #4085AC
color K #000000

cell a ▄ B .
cell d ▛ B K
cell n █ B K

frame idle
..a..a..
<其余 3 行别名>
end

action click
press 75
rise 100
land 100
end
```

### 1.1 颜色与终端格

- `color ALIAS #RRGGBB` 定义颜色；`.` 表示不设置颜色。
- `cell ALIAS GLYPH FOREGROUND BACKGROUND` 定义一个完整终端绘制指令。
- `GLYPH` 使用常见 Block Elements：`▘▝▀▖▌▞▛▗▚▐▜▄▙▟█▂▆`。
- `space` 表示空格字符。它只有设置背景色时才可见，不能把没有前景色和背景色的空格定义为格子。
- `cell` 别名必须是单个非空白 ASCII 字符，且不能使用保留的 `.`。

例如 `cell d ▛ B K` 的含义不是“蓝色像素加黑色像素”，而是“输出字符 `▛`，前景色为 `B`，背景色为 `K`”。构建和绘制阶段都不能把它改写成看似等价的另一个字符。

### 1.2 帧

- `size 8 4` 指最终终端画布，不是源图片尺寸。
- 每个 `frame` 必须恰好包含 4 行，每行恰好包含 8 个已定义的 `cell` 别名或 `.`。
- 帧中的 `.` 是完全透明的格子；绘制时不覆盖缓冲区原有内容。
- `idle` 帧必须存在；没有动作播放时绘制它。
- 帧和动作名称使用小写 kebab-case，并且不能重复。

编辑静止造型时只修改 `idle` 的 `8×4` 别名网格。需要新的字符、前景色或背景色组合时，先增加一个 `cell` 定义，再在帧中引用它。

### 1.3 动作

- 动作的每一行使用“帧名 + 持续毫秒数”。
- 持续时间必须是 25 毫秒的倍数，范围为 25–250 毫秒。
- 一个动作包含 1–8 个步骤，总时长不超过 600 毫秒。
- 动作结束后回到 `idle`，动作表中不重复写 `idle`。
- 当前产品只要求 `click`，不允许无人操作时循环播放。

当前 `click` 是 `press → rise → land → idle`。所有帧共用同一个 `8×4` 画布，动作不能推动右侧文字或改变 Welcome 高度。

## 2. 为什么不用像素自动编码

旧方案先画 `16×16` 逻辑像素，再把每组 `2×4` 像素自动转换成一个字符。它能保留抽象像素，但会产生 `U+1CCxx` 一类较新的字符；终端字体可能缺字，也可能让轮廓比 `▀`、`▄`、`▛`、`▜` 等常见字符更粗或更碎。

现在的边界更简单：

| 对象 | 责任 |
| --- | --- |
| `pet.sprite` | 直接保存字符、前景色、背景色、帧和动作时序 |
| `zeta-sprite` | 解析、校验并保留每个终端格，不重新选择字符 |
| `tui/build.rs` | 构建时生成 Rust 数据并写入 Cargo `OUT_DIR` |
| `app/welcome/pet.rs` | 绘制所有非透明格，包括带背景色的空格 |
| `App` 的 Welcome 状态 | 以后拥有当前动作、步骤和下一次换帧时间 |

SVG 和 PNG 仍可由 `zeta-sprite` 转成块字符，用于独立图片转换；它们不再是 Welcome Pet 的设计源，也不会自动生成 `pet.sprite`。

## 3. 点击行为

Pet 是装饰图形，动作不改变 Session、Thread、模型或输入状态。计划中的触发入口只有鼠标左键：在 Pet 区域按下并在同一区域松开，而且中间没有拖动时播放一次 `click`。

鼠标拖动继续属于终端文字选择。动作播放期间再次点击时，从 `click` 第一帧重新开始；切换页面、Pet 被隐藏或应用退出时立即回到 `idle`。Pet 不获得键盘焦点，不添加边框、按钮文字、悬停底色、声音或 Transcript 消息。

动作不需要独立线程。现有终端事件源以 25 毫秒为轮询间隔产生 `Tick`，可以推进每个动作步骤并请求重绘。

## 4. 预览和验收

```bash
just pet
just pet frames
just pet click
```

- `just pet` 打印 `idle` 的彩色 `8×4` 结果。
- `just pet frames` 打印所有帧，逐格检查字符和颜色。
- `just pet click` 按真实时序播放一次动作并回到 `idle`。

每次修改 Pet 时执行：

```bash
just pet frames
just pet click
just test zeta-sprite
just test zeta-tui welcome
```

验收要求：

1. 所有帧都是 `8×4` 终端格，Welcome 预留 `8×5` 区域。
2. 快照分别检查字符、前景色和背景色，不能只还原成逻辑像素比较。
3. 带背景色的空格必须写入 Ratatui Buffer；只有三项都为空的格子才透明。
4. 预览中不出现 `U+1CCxx` 八分块字符。
5. 在真实终端中查看一次，确认当前字体下没有缺字、明显接缝或比例走样。
6. 点击交互完成后，再验证命中、拖动不触发、重复触发、换帧和回到 `idle`。

## 5. 长期不变量

- Pet 的可编辑内容只有 `pet.sprite`，不能同时维护 SVG、PNG、字符画或生成后的 Rust 数据。
- 每帧固定为 `8×4` 终端格，Welcome 区域固定为 `8×5`。
- `pet.sprite` 直接决定最终字符、前景色和背景色，编译器不能自动替换字符或交换颜色。
- Welcome Pet 只使用格式允许的常见 Block Elements，不使用 Braille 点阵或 `U+1CCxx` 八分块字符。
- 动作只在明确触发后播放一次，不持续循环，不改变 Welcome 布局。
- 修改动作时必须编辑设计源并运行预览和测试，不能直接修改构建产物。
