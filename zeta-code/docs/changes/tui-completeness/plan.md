## 运行验证

检查期间仓库版本发生变化。正式验证前记录实际提交及未提交差异，再核对受影响的正文、输入路由和终端行为。

从仓库根目录按受影响模块选择检查，测试名过滤器应来自实际存在的测试：

```sh
just check zeta-tui
just test zeta-tui --lib
just test zeta-cli --test tui_real_scenarios
```

CLI 的真实 PTY 文件使用 `cfg(unix)`，因此上述入口不能证明 Windows 已验证。运行前还要确认测试依赖和目标环境；命令退出成功但没有运行目标场景，也不能算通过。

终端历史按[兼容性记录](../../../tui/README.md#终端历史兼容性验证)生成生产输出样本，在 Q-2 选定的终端与复用器组合中验证。涉及共享后端行为时，再补对应包的检查，不直接扩大为整个 workspace。

验证失败后，先把实际原因写入对应 AC，再确定补丁。优先修复丢失输入、操作错会话、权限结果错误和退出破坏终端的问题，其次是流程中断，再是阅读与提示问题；不能为了让验收通过而降低规格要求。
