# Issue 开发与 PR

候选实现已接入 CLI/TUI，验收仍在进行；实际结果见[本次记录](../changes/2026-09-07-issue-manager/verification.md)。图形产品和独立 PR 审查列表不属于本次功能。

## 选择与开始

- 在空白会话向右，或输入 `/issue`，打开 Issue 管理器。服务端从当前仓库的 `origin` 识别 GitHub 仓库，使用服务端主机已安装并登录的 `gh`。origin 的获取和推送地址必须指向同一仓库。
- Issue 面板与命令面板共用标题线、内边距和主题选中态。Open / Closed 页签分别查询开放和已关闭的 issue，初次打开选中 Open；切换清除当前选择、过滤和分页，忽略旧请求的迟到结果。
- ↑↓、Home/End、PageUp/PageDown 导航；Space 多选；Enter 阅读正文与评论；`/` 过滤已加载条目，`n` 读取下一页，`r` 刷新。列表内 Tab/Shift+Tab 移动到底部动作或返回；列表首项按 ↑ 或 Shift+Tab 回到页签，←→/Tab/Shift+Tab 切换页签，↓/Enter 进入列表。空列表、加载与失败有明确提示，Esc 返回。
- 一次选择 1–20 个 issue，合并为一个新 Session。选择“当前分支”使用本地 HEAD；选择“main”先获取 origin/main。两者都固定提交身份，创建独立工作目录，保留原目录和未提交修改。
- 输入框显示原子的 `[issue #3]` 标签。用户可以补充要求后发送；标签提交结构化编号，后端只接受当前 Session 已关联的 issue。直接键入相同文字不会生成关联。
- 后端保存正文、评论、链接与读取时间。单个或整组选中内容超过容量限制时显示错误，不提交不完整材料。尚未发送的 issue 标签可在恢复会话时重新加载；普通文字草稿沿用既有会话恢复边界。
- 恢复 issue 标签失败时，按 1、2、4、8、16、30 秒间隔重试，之后保持 30 秒；间隔从请求失败完成时计算。连续失败只在正文提示一次，恢复成功后停止请求；空结果也视为加载成功。切换 Thread 后重新加载，旧 Thread 的迟到结果不能改变当前标签或重试间隔。

## 创建 PR

开发 Turn 结束后使用 `/pr`。页面展示任务分支、目标分支、标题及文件数量，`i` 阅读正文、起始提交、目标提交与完整文件列表。

| 选择 | 行为 |
| --- | --- |
| 创建 PR | 提交任务变更、推送任务分支、创建普通 PR |
| 创建草稿 PR | 执行同样准备，创建草稿 |
| 自动 Merge / Squash / Rebase | 创建普通 PR，然后请求按仓库条件合并；只展示仓库允许的方式 |

发布前重新核对文件树。预览后代码改变、变更捕获不完整或提交冲突时停止并显示原因。开发起点和 PR 目标分别保存；当前 PR 目标为 main，页面明确展示比较范围。

创建成功后保存 PR 身份；自动合并失败不删除 PR。再次操作先查已有 PR，避免重复创建。`r` 重新读取 PR、检查及合并状态；状态无法读取时明确显示不可用，不能用 Agent 完成状态代替 PR 合并。

关闭查询页面不重新打开迟到结果。已提交的任务创建或发布操作可能继续完成，关闭页面不表示撤销后端操作。

## 合并推荐配置

- Config 总页提供“推荐合并处理”勾选项，默认开启；它不控制普通 issue 浏览、手动多选或 PR 合并方式。
- 独立的 Issues Tab 配置分析模型。关闭勾选项后，该 Tab 保留显示但置灰，键盘导航跳过它，已选模型继续保存。重新开启后可继续编辑。
- 没有配置模型时显示选择提示，不继承当前对话模型。模型选择器只展示已配置供应商的模型，允许明确清除选择；返回时保留 Issues 页位置。
- 设置保存在后端 profile 的 `config.toml`，由 `[issues].recommendMerge` 和 `[issues.analysisModel]` 的 `provider`、`model` 表达，不写入 `[tui]`。保存使用预期配置版本；过期修改不能覆盖新的设置。
- 相似 issue 分析执行仍待接入；配置页面本身不调用分析模型，也不把“开关开启”显示为“分析完成”。
