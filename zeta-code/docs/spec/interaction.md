# TUI 交互规格

本文规定输入、导航、确认和返回行为。下列键表使用默认键位；用户可修改的范围见[快捷键声明与保存](commands.md#快捷键声明与保存)。

按键由当前操作上下文解释。先看焦点在输入框、列表还是阅读区，再判断按键做什么；不能因为界面叫“面板”就给它统一的字母命令。布局上的浮层和输入上的独占是两个独立概念。

| 当前正在做什么 | 字母如何处理 | 退出原则 |
| --- | --- | --- |
| 写消息、搜索、编辑设置 | 输入文字 | 结束当前编辑；不同时操作背景列表 |
| 选择会话或列表条目 | 执行该列表明确提供的动作，其余字符不写进草稿 | 回到进入前的界面或输入区域 |
| 阅读预览或详情 | 滚动与阅读动作，不编辑内容 | 关闭当前阅读界面并恢复返回位置 |
| 录制快捷键 | 字母和组合键都是待录制数据 | 取消录制并返回设置列表 |
| 回答提问或审批 | 明确选择并提交 | 待处理请求必须有明确结果；Esc 不代替回答或拒绝 |

统一的是输入归属、焦点表达和返回规则；具体动作仍取决于对象。Enter 在普通会话上打开，在归档会话上恢复；Space 在会话列表上预览，在多选列表上可以切换选择。操作提示必须与当前动作一致。

## 按键上下文

- 上下文由页面、活动组件和组件内部焦点共同决定。
- 命令面板可以在页签、搜索框、列表和编辑框之间切换；从列表进入搜索时，字符解释立即变成文字输入。
- 无需额外建立一个跨页面的 Normal / Insert 模式；输入框自身已有的编辑模式仍由输入框负责。

“独占输入”表示当前交互先解释事件，并阻止无效按键误触背景。它不要求铺满终端，也不要求覆盖背景。详情浮层、Session 预览和命令面板都可以独占按键；输入补全则属于输入组件的编辑上下文，候选导航不能把普通文字变成命令。

- 当前应用先处理详情浮层、会话预览和已聚焦的管理列表，再处理待回答请求、命令面板与 Queue；其后才经过适用的应用快捷键、页面导航和输入组件。
- 具体可用快捷键以各上下文的处理器为准，不能声称应用快捷键在任意面板内都能穿透执行。
- 实现入口是 [`App::handle_key_at_in_area`](../../tui/src/app/state.rs)。

## 统一按键与界面键表

- 键位先由动作决定，再由当前对象提供具体行为。
- 基础导航在共享 `Navigation` 中解释；命令面板复用 `ListSelection` 的搜索、焦点、确认与退出规则。
- 字母只在列表或只读上下文里作为命令；搜索、文本编辑、自定义回答和快捷键录制先处理自己的输入。
- 不能为了让键表看起来一样而抢走文本字符。

### 共用规则

| 按键 | 列表 / 选择区 | 只读阅读区 | 搜索 / 编辑 / 录制 |
| --- | --- | --- | --- |
| ↑ / k、↓ / j | 上一项、下一项；首尾停止 | 上一行、下一行 | 字母是输入；搜索的方向键可转移焦点，录制中的方向键也作为待录制键 |
| Home / End | 第一项、最后一项 | 已加载内容首尾 | 保留给当前编辑器，不导航背景；当前简单搜索框不支持光标首尾编辑 |
| Ctrl+Home / Ctrl+End | 与 Home / End 同义 | 与 Home / End 同义 | 不操作背景 |
| PageUp / PageDown | 分段移动当前项 | 按当前阅读视口翻页 | 不操作背景 |
| / | 有搜索能力时进入搜索框 | 没有搜索能力时无动作 | 输入 `/`；录制时记录 `/` |
| Enter | 执行当前主动作；页签焦点下进入列表 | 无提交动作 | 搜索返回结果列表；字段编辑保存；自定义回答提交；录制按其阶段记录 |
| Space | 开关类条目切换；会话行预览；具体见[命令面板](commands.md)与[会话管理](sessions.md) | 不自动跳到下一页 | 输入空格；不能同时激活候选 |
| Tab / Shift+Tab | 页签焦点下循环切页；选项焦点下调整当前值；Enter 进入该页列表，↓ 进入搜索或列表 | Status 循环切换页签 | 搜索中不参与导航；编辑和录制由当前组件处理，不穿透到父页签 |
| ← / → | 页签焦点下切页；列表焦点下按条目能力调整值 | Status 无编辑内容，左右也切页 | 不切背景页签 |
| Esc | 返回父面板或输入框 | 关闭当前阅读界面，恢复进入位置 | 搜索回列表且保留查询；编辑或录制取消当前步骤 |

- 命令列表首项或空列表按 ↑ 进入搜索框，没有搜索框时进入页签；搜索框 ↑ 进入页签，页签 ↓ 进入搜索框，没有搜索框时进入列表。
- 长按方向键不跨区域，松开后再按才转移焦点；列表中的 j/k 到边界停止，不进入搜索框。
- 管理列表、Queue、Agents 和正文条目选择仍在首尾停止，退出使用 Esc。
- 搜索框 ↑ 可进入页签区，↓ 或 Enter 回到列表；按 Enter 返回列表后，还需要再按一次 Enter 才会执行条目。
- 列表与阅读支持长按导航；打开、展开、调整值、切页、提交、恢复、删除和关闭只处理首次 Press，Release 不执行动作。

- PageUp/PageDown 的目标统一为快速浏览当前区域，步长由内容决定：普通命令列表与管理列表每次 12 项，正文条目选择每次 12 条，Queue 每次 3 项，Agents 每次 4 项；Status、详情和会话预览使用当时的正文视口行数。
- 阅读中的 ↑/↓/j/k 每次一行；详情浮层滚轮每次移动一行，不改变键盘当前项和焦点。
- 会话预览向上到达已加载内容顶部时请求更早历史；短详情没有历史加载动作。

### 统一程度与设计理由

- 相同的浏览动作共用键位，长按导航不跨焦点区域。
- Enter 始终是当前对象的主动作；Space 留给对象的辅助操作，因此开关切换、会话预览和正文展开各有明确对象。
- Esc 返回一层，搜索查询、父列表当前项与草稿应保留；待回答审批和提问需要明确业务结果，是有意保留的例外。
- 删除保持 Ctrl+X 或 Delete 这样的专门按键，不增加全局 `d`；也不另设全局 `q` 关闭。

- 新增界面必须先在对应键表中写出入口、当前焦点、导航、主动作、Space、Esc、文本输入和自动重复的含义，再选择共享控件。
- 验收同时检查按键产生的状态与动作、焦点提示、嵌套返回、输入和粘贴隔离、异步完成后的目标身份，以及鼠标和键盘进入同一个业务动作。
- 快捷键已实现但提示未更新、文档列出快捷键但没有事件路径，都视为未完成。

## 交互状态

| 交互事实 | 含义 | 是否改变键盘当前项 |
| --- | --- | --- |
| 焦点 | 当前区域接收键盘输入 | 否 |
| 可操作内容 | 目标拥有打开、展开或提交动作 | 否 |
| 键盘当前项 | Enter、Space 或方向键将作用的目标 | 是 |
| 已生效项 | 当前页签、模式或已经应用的值 | 否 |
| 鼠标悬停 | 指针当前位于可交互目标上 | 否 |
| 鼠标按下 | 左键按下，尚未确定点击或拖动 | 否 |
| 禁用 | 可见但不能操作 | 否 |
| 文字框选 | 选择当前终端帧中的字符 | 否 |

- 焦点、键盘当前项、已生效项、悬停和按下可以同时存在，不能压成一个状态。
- 鼠标移动不覆盖键盘当前项。
- 具体字符、颜色和无颜色表达由[样式契约](styles.md#交互状态的绘制)统一规定。
- 正文可点击链接的当前缺口见[功能现状](../capabilities.md#明确缺口)。

每个可交互目标分别保存：所在区域是否有焦点、目标是否已生效或禁用、目标是否为键盘当前项、鼠标是否悬停、鼠标是否按下。功能状态中的成功、警告和失败不属于交互状态，不能代替焦点、选择或悬停。

交互事实如何映射为颜色、标记和文字属性，见[交互状态的绘制](styles.md#交互状态的绘制)。

- 命令面板中的页签统一复用 `TabListState`：`Tab` 或右方向键切换到下一页，`Shift+Tab` 或左方向键切换到上一页，首尾循环。
- 当内容区也使用左右键调整当前项时，只有页签区获得焦点后才切换页签；选项区的 `Tab` / `Shift+Tab` 与右 / 左方向键一样调整当前项的值；搜索框不处理 Tab / Shift+Tab，左右只移动输入光标。
- 页签区获得焦点后的切页和进入正文由 `TabListState` 统一解释；正文到达上边界时报告给父面板，由父面板交接焦点。未绘制的内部页签不能接收焦点。

## 操作提示文案

- 操作提示随实际焦点变化：列表显示条目动作，页签显示切页和返回列表，搜索显示返回结果列表，编辑与录制显示提交或取消。
- 基础导航（方向键、`j/k`、Home/End、PageUp/PageDown）不常驻操作提示行，按键仍然可用。
- 宽度不足时先省略次要动作，保留完整的 Esc 返回提示；完整键表由本文和 `/help` 承担，不能为了塞满一行而截断关键按键或删除 `to`。

- `KeyHints` 与 HitBar 中的操作提示统一写成 `<按键> to <动作>`，按键名使用界面中的标准大小写，例如 `Esc`、`Enter`、`Space` 和 `Ctrl+X`。
- 共享的 `KeyHints` 和 `ListSelection` 接口接收动作本身并统一补上 `to`，调用处不能自行拼接 `Esc close`、`Enter apply` 等文案。

- `Esc` 的动作必须按退出后的结果命名：关闭当前临时界面并恢复原上下文用 `Esc to close`；放弃编辑、录制、自定义输入或等待中的组合键用 `Esc to cancel`；从列表选择或 Thread 切换焦点回到聊天输入区用 `Esc to return to input`。
- `Esc Esc` 表示连续按两次 Esc 的真实快捷键序列，不属于操作提示句式，不改写。

## 所有权与实现约束

- 组件拥有焦点、当前项、已生效项、禁用和命中结果；应用层拥有当前页面的悬停与按下目标；统一渲染底座接收这些独立事实，并按[样式契约](styles.md)映射为 Ratatui `Style`；主题资源拥有颜色读取、校验和终端色阶转换。
- 命令面板只提供产品内容和动作身份，不能直接使用 Ratatui 固定颜色，也不能把产品结果颜色当成交互颜色。

- 交互验收至少覆盖：键盘当前项与另一行悬停同时可见、按下与拖动分流、禁用项没有鼠标反馈、已生效 Tab 失焦后仍可识别，以及无颜色终端下不依赖颜色的状态区别。
- 样式验收另外覆盖 Dark、Light、Colorblind 颜色映射、ANSI 色阶转换和固定字符角色。
- 测试使用 Ratatui buffer 中的语义样式和状态断言，不使用截图作为通过依据。

终端历史的已记录验证范围和复现命令统一见[实现手册](../../tui/README.md#终端历史兼容性验证)，不能从本文的行为约定推断所有终端均已验证。
