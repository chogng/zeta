# TUI 布局规格

本文只维护页面部位、空间分配和覆盖顺序。正文单元的输出示例见[正文输出](transcript.md)。按键行为见[交互规格](interaction.md)，颜色与字符规则见[样式规格](styles.md)。

描述一个界面时先说它在哪里、负责什么，再说明高度和按键。页面、区域、面板、浮层描述的是位置与职责；占满剩余空间、随内容增长、固定行数描述的是高度策略。显示时间长短和是否只读也各自独立，不能用“临时面板”包办这些区别。

| 遇到的界面 | 应该怎么称呼 | 高度如何分配 | 谁接收按键 |
| --- | --- | --- | --- |
| 正常聊天 | Session 页面 | 已完成正文顺序追加；交互区域按可变正文和辅助区域申请高度 | 当前焦点区域；默认是输入框 |
| 浏览会话列表 | Session 管理页面 | 列表占据 Welcome 下方的剩余空间 | 输入框或已聚焦的管理列表 |
| Space 打开的聊天 | Session 页面预览 | 正文占满剩余空间，底部显示只读身份与退出提示 | 预览独占按键，支持滚动；Esc 回到原列表 |
| `/model`、`/config` 等 | 输入位置中的命令面板 | 面板提供期望高度，页面裁剪到可用空间 | 当前搜索、列表、页签或编辑上下文 |
| 会话元数据、执行完整输出 | 详情浮层 | 根据内容申请高度并受覆盖区域限制，不挤压背景 | 浮层独占按键；Esc 关闭并恢复原焦点 |
| `/`、`@`、`$` 候选 | 输入补全浮层 | 根据候选数量增长且有最大高度，不挤压正文 | 输入组件同时处理文字、候选导航和确认 |

具体部位见下文页面词典；高度策略见[高度与缩放规则](#高度与缩放规则)，按键上下文由[交互语义](interaction.md#按键上下文)统一规定，各界面的完整键表见[统一按键与界面键表](interaction.md#统一按键与界面键表)。

## 页面、区域、面板与浮层

下面四个问题要分别回答；一个名称不承担所有分类。

| 问题 | 使用的概念 | 判定方式 |
| --- | --- | --- |
| 它在哪里？ | 页面、区域、面板、浮层 | 页面组织整屏；区域是页面分配的矩形；面板是放入区域的操作内容；浮层覆盖已画好的页面 |
| 它多高？ | 占满剩余空间、按内容申请高度、固定行数 | 按任务需要选择；可选上限和缩小时的裁剪另外说明 |
| 谁接收按键？ | 当前焦点、独占输入、文字输入、选择、阅读、录制 | 由交互状态决定；有边框、覆盖背景或占满终端都不能替代这个判断 |
| 关闭后回哪里？ | 返回页面、返回父面板、返回输入框 | 保存需要恢复的当前项、滚动位置与草稿；短暂显示不产生新的布局类型 |

- “模态”在本文只表示当前交互独占输入，背景不执行该交互消费的按键；具体分发规则见[按键上下文](interaction.md#按键上下文)。
- 模态不等于浮层：命令面板参与纵向布局也可以独占输入；输入补全虽然是浮层，仍与输入框共同完成编辑。
- 只读也不等于模态：Status 是只读命令面板，Session 预览是只读页面内容，二者使用不同的空间分配。

选用容器时，持续浏览一段完整对话使用页面正文区；模型选择、设置和参数编辑使用输入位置中的命令面板；保留背景作为参照的短详情使用详情浮层；输入候选使用补全浮层。普通长内容先采用内部滚动，不因内容变多就另造一种“全屏面板”。

## 高度与缩放规则

高度统一分成三种策略。不要把“自适应”单独当成类型，也不要用“吃终端高度”判断是不是面板。

| 高度策略 | 计算方式 | 适用内容 | 溢出处理 |
| --- | --- | --- | --- |
| 占满剩余空间 | 总高度减去同级已分配区域 | 会话正文、管理列表、预览正文 | 在已分配视口内滚动 |
| 按内容申请高度 | 取内容所需高度与页面可用高度的较小值；有组件上限时再受其限制 | 多行输入、审批、提问、命令面板、详情与补全浮层 | 组件内部滚动；固定标题与提示保持可见 |
| 固定行数 | 按界面契约预留行数，极小终端仍按可用空间裁剪 | Goal、Plan、TopTip、底部操作提示 | 简写或截断；不能挤出负高度 |

- “固定最大高度”是内容高度的可选上限，不等于始终占用该高度。
- 短列表不应为了填满上限而留出大块空白；长正文也不应为了保持面板外形而丢掉可用阅读空间。
- 需要页签稳定时，可按所有页签的最大内容高度申请空间，避免切页跳动；这仍是内容高度策略。
- 浮层也遵守这三种策略，但它的可用空间来自覆盖区域，不从背景正文扣除。

- 当前命令面板由标题、空白行、可选页签和正文共同计算期望高度。
- `ListSelection` 按过滤后的全部条目数申请列表高度，没有固定 12 行上限，搜索框和条目说明另计；Status 按所有页签的最大内容高度申请；详情浮层按内容申请并受覆盖区域限制。
- 这些都不是固定占满终端的面板，也不能笼统称为“固定高度面板”。

- 没有内容的 Goal、Plan、Queue、Query 和 Agents 高度为 0，不留下空壳。
- 普通聊天的正文区拿走组件分配后剩余的高度，空间允许时至少保留 4 行。命令面板打开时优先使用除底部操作提示之外的全部高度，正文可以缩至 0；TopTip、Goal、Plan、Queue 和 Agents 暂不占高。
- 普通聊天的顶部提示固定占用一行；没有提示文字时这一行保持为空。
- 输入框高度随多行草稿变化；审批面板和命令面板会用自己的高度替换它。
- 输入位置下方固定占用两行。常态显示 `StatusLine`；命令面板或其他需要明确操作的交互打开时，首行留空，末行显示操作提示。
- 底部两行和 Agents 都出现时，中间保留一行；只出现一方时不保留。
- Session 管理页面在可用空间允许时至少给 Session 列表保留 4 行；终端变矮时先压缩 Welcome。

- 页面负责最终矩形，组件负责期望高度与内部滚动。
- 标题、页签、正文和操作提示必须共用同一份布局结果进行绘制和鼠标命中；不能绘制时临时多挤一行。
- 极小终端可能放不下完整组件，此时各区域裁剪到非负高度，不能覆盖底部或越界；“至少 4 行”以可用空间足够为前提。

因此，定位“组件消失”问题时必须附上终端宽高。`80×24` 表示 80 列、24 行。

## 当前页面

整个终端可见范围叫 **屏幕**（Screen）。当前区分两种顶层页面；Session 页面可以用可输入或只读预览方式打开：

| 中文名称 | 代码名称 | 怎么认 |
| --- | --- | --- |
| Session 页面 | `TerminalScreen::Session` | 能看到对话正文、输入框和状态行 |
| Session 管理页面 | `TerminalScreen::Manager` | 能看到 Welcome 和按状态分组的 Session 列表 |

不要只说“主页面”或“列表页”。直接说“Session 页面”或“Session 管理页面”。

## 行首标记栏

- 正文、输入和选择列表中的内容行通常把最左侧两个终端格保留为 **标记栏**（marker gutter）：第一个格显示标记，第二个格负责把标记与正文隔开。
- 正文因此通常从第三个终端格开始。
- 标记栏是跨组件共用的横向对齐规则，不是一个独立的页面区域。

“标记栏”比“装饰列”更准确，因为这里的字符会表达角色、状态、层级或当前操作目标，不只是视觉装饰。终端的一“列”只能容纳一个显示格，所以描述整个两格结构时用“栏”，描述其中某一格时才用“列”。

```text
标记栏  正文
┌──┬───────────────────────────────────────────────────────┐
│> │ 用户输入                                              │
│● │ Agent 或系统输出                                      │
│> │ 键盘当前项                                            │
│  │ 上一行正文的续行                                      │
└──┴───────────────────────────────────────────────────────┘
```

| 标记 | 当前用途 | 常见位置 |
| --- | --- | --- |
| `> ` | 用户输入、可输入位置或键盘当前项 | 输入框、历史用户消息、已结束的本地命令、审批、提问和各种选择列表 |
| `● ` | Agent、系统或正在执行的输出；颜色再表达具体状态 | 正文单元、Agents 中当前查看的 Thread |
| `○ ` | 非当前项或非活动项 | Agents 中其他 Thread |
| 两个空格 | 此行没有独立标记，但正文仍与其他行对齐 | 多行正文的续行、未选中的列表项 |

- 有层级关系的内容可以把标记栏扩展为连接前缀，例如展开详情使用 `└─ `，表示下一行属于上一条输出。
- Session 管理页面的各分组标题处于同一层级，只显示名称和数量，不增加展开符号；当前标题仍使用统一的标记栏。
- 标题和会话行的缩进表达归属，可折叠行为见[交互契约](sessions.md#session-管理列表的动作)。

- 输入框边线、空行以及 Goal、Plan、未聚焦的 Queue、状态行等整行辅助信息不需要伪造标记来填满标记栏；Queue 获得键盘焦点后，当前项使用 `>` 表达操作目标。
- 标记栏不是独立布局区域，由各组件按上述前缀和对齐规则分别绘制；定位问题时仍统一称为“标记栏”。

## Session 页面

下面是各区域都出现时的纵向顺序。实际界面会隐藏没有内容的区域，所以它们不一定同时可见。

```text
┌──────────────────────────────────────────────────────────┐
│ 正文区 Transcript                                        │
│   ├─ Welcome（正文历史起点）                             │
│   └─ 正文单元 Transcript Cell                            │
│            Ctrl+End to jump to bottom ↓（离开最新位置时）    │
│                                                          │
├──────────────── Goal 行（有目标时）─────────────────────┤
├──────────────── Plan 行（有进行中计划时）───────────────┤
├──────────────── Queue 区（有排队消息时，最多显示 3 条）─┤
│ Query 面板（Agent 提问时，位于输入位置上方）             │
│ 顶部提示 TopTip（固定一行，提示为空时留空）              │
├──────────────────────────────────────────────────────────┤
│ 输入位置 Composer Position                               │
│   通常显示 ChatInput；也可能被 Approval 或命令面板替换    │
├──────────────────────────────────────────────────────────┤
│ 输入位置下方两行                                          │
│   常态显示 StatusLine；交互时首行留空                     │
│   末行显示操作提示 KeyHints                                │
│                                                          │ ← 条件性间隔
│ Agents AgentThreadSwitcher（有被委托 Agent 时）          │
└──────────────────────────────────────────────────────────┘
```

### 固定区域词典

| 推荐名称 | 代码名称 | 内容与边界 |
| --- | --- | --- |
| 正文区 | `transcript` / `ChatHistory` | 对话内容占据的主要滚动区域；Welcome 是历史起点，内容溢出后随正文滚走，回到顶部时重新出现 |
| 正文单元 | `TranscriptCell` | 正文区内的一条用户消息、Agent 回复、命令或工具结果；“某条消息”要定位到这一层 |
| 回到底部控件 | `JumpToBottom` | 仅在正文离开最新位置时覆盖在正文区最后一行中央；它紧邻 `TopTip` 上方，但仍属于正文区，不占用或改写 `TopTip` |
| Goal 行 | `goal` | 一行 `Goal: …`；无目标时高度为 0 |
| Plan 行 | `plan` | 一行 `Plan 已完成数/总数: 当前步骤`；计划结束后隐藏 |
| Queue 区 | `queue` | 输入在当前 Turn 结束后再发送时，显示排队消息；Alt-Up 进入选择，普通输入框不属于这里 |
| 提问面板 | `request` / `Query` | Agent 要求用户选择或输入答案时出现，位于输入位置上方 |
| 顶部提示 | `top_tip` / `TopTip` | 输入位置上方固定占用一行；提示文字右对齐，没有内容时整行留空，不与上方区域共享字符 |
| 输入位置 | `composer` / Composer Position | 页面为输入相关组件预留的位置；它是位置名称，不等于输入框 |
| 输入框 | `ChatInput` | 有上下边线、包含输入提示符和草稿文字的编辑框；这是输入位置的默认内容，具体字符见[样式契约](styles.md) |
| 状态行 | `StatusLine` | 输入位置下方的常态信息行，显示权限模式、模型、Git、Plan、Subagent 等摘要；可选显示本机进程常驻内存与 CPU 占用。Queue 只由输入框上方的 Queue 区表达 |
| 操作提示行 | `KeyHints` | 某个交互需要明确操作时显示在输入位置下方两行的末行，例如 `↑↓ to choose · Enter to confirm`；首行保持为空白分隔 |
| Agents | `agent_thread_switcher` / `AgentThreadSwitcher` | 页面最下方的 Agent Thread 列表；一行一个 `main` 或被委托 Agent，Enter 切换当前 Thread，只在存在被委托 Agent 时出现 |

### 输入位置里可能出现什么

“Composer”最容易被误当成输入框。准确说法是：**输入位置是槽位，输入框只是默认放进去的组件。**

- 代码中的 `ChatPanel` 负责 Session 页面底部整块聊天交互区：固定内容包括 `TopTip` 和 `StatusLine`，按状态出现的内容包括 `ChatInput`、`Approval`、`Query` 和 `CommandPanel`。
- “固定”和“临时”只描述显示周期，不再各自形成一种容器类型；页面上的具体内容仍使用下表名称。

- 本地 Slash Command 打开并替换输入框的界面统一称为**命令面板**，具体面板使用标题加“面板”，例如 Session 面板、Model 面板、Theme 面板、Config 面板和 Status 面板。
- 是否包含候选列表、搜索或编辑能力不再产生新的产品术语。

- 命令面板使用 `─ 标题 ─…` 这一种标题栏。
- `CommandPanel` 一次分配标题栏、固定空白行、可选页签区和正文区；绘制、高度计算与鼠标命中共用这组区域。
- 标题栏独占第一行，下方固定留一行空白，页签只出现在空白行之后，正文只出现在完整页签区之后。
- 窄宽度导致页签换行时，只增加页签区高度，不改变标题与正文的顺序。
- 页签区和正文区共用左右各两格的内容缩进；列表的状态标记单独占用正文左侧两格，不改变文字起点。
- 完整字符、间距与样式规则见[样式契约](styles.md#命令面板标题)。

- `CommandPanel` 是 `ChatPanel` 内当前命令面板的代码容器；`Picker`、`Editor` 和 `Panel` 等后缀只表达代码内部职责，不作为用户描述界面时的分类。
- 输入 `/` 时出现的候选尚未执行命令，应称为 Slash Command 补全浮层，不叫命令面板。

| 当前内容 | 推荐叫法 | 与其他区域的关系 |
| --- | --- | --- |
| 普通草稿输入 | 输入框（`ChatInput`） | 默认占用输入位置 |
| 权限确认 | 审批面板（`Approval`） | 替换输入框，占用输入位置 |
| `/status`、`/theme`、`/model`、`/config`、`/resume` 等本地命令界面 | 命令面板；需要具体定位时使用标题加“面板” | 替换输入框，占用输入位置；内部可以显示信息、候选列表、搜索或编辑内容 |
| Agent 的结构化问题 | 提问面板（`Query`） | 不替换输入位置，而是在它上方单独占区；需要自由输入时仍使用下方输入框 |

### Status 面板

- `/status` 占用输入位置，包含 Thread 与 Processes 两页，各页独立保留滚动位置。
- 高度按两页中最大的完整内容申请，避免切页跳动；空间不足时按可用区域裁剪并滚动，至少 4 行以可用空间足够为前提。
- 字段、统计口径、不可用状态和采样触发见[状态与资源](status.md)。

### 输入框附近的两种提示

| 推荐名称 | 位置 | 用途 |
| --- | --- | --- |
| 顶部提示 | `TopTip` | 在输入位置上方固定占用一整行，文字靠右；剪贴板有图片时限时显示 `image in clipboard · ctrl+v to paste`，否则按状态显示空会话导航或限时权限提示；临时通知优先于剪贴板图片提示，所有内容切换都不改变这一行的高度 |
| 操作提示行（HitBar） | `KeyHints` | 位于输入位置下方两行的末行；交互时替换状态行的末行，首行保持为空白分隔，底部两行总高度不变 |

- 因此，剪贴板图片提示、`← for agents` 和 `shift+tab to cycle policy` 都属于顶部提示；输入框下方的权限模式、模型和 Git 信息才属于状态行。
- 这里没有轮播：权限提示由首次进入对话或切换权限策略触发，剪贴板图片提示由启动和窗口重新获得焦点时的检测触发。
- 临时通知、剪贴板图片提示和权限提示都在距最后一次触发 5 秒后直接消失，重复触发会重新计时；图片粘贴成功时还会立即清除剪贴板提示。

## Session 管理页面

Session 管理页面复用正文区的位置，但内部改为 Welcome 和 Session 列表：

```text
┌──────────────────────────────────────────────────────────┐
│ Welcome                                                  │
│                                                          │ ← 有空间时保留 1 行
│ Session 列表 Session Manager                             │
│   ├─ 同级分组标题                                        │
│   └─ Session 行：图标 / 名称 / 当前操作或问题 / 时长      │
│ 顶部提示 TopTip（固定一行，提示为空时留空）              │
├──────────────────────────────────────────────────────────┤
│ 输入位置：ChatInput 或命令面板                           │
├──────────────────────────────────────────────────────────┤
│ 空白分隔行                                               │
│ 操作提示栏 HitBar（KeyHints）                           │
└──────────────────────────────────────────────────────────┘
```

Session 列表内部按以下横向结构排列：

```text
  Idle (2)                                ← 同级分组标题
> ○ Session 名称     当前操作或问题    2h ← 键盘当前 Session
  ○ 另一 Session                         ← 普通 Session
└─┘└┘└──────────────┘└──────────────┘└──┘
 标 状态     名称          活动          时长
 记 图标
 栏
```

| 横向部位 | 宽度与位置 | 内容与边界 |
| --- | --- | --- |
| 分组标题 | 独占整行，文字位于标记栏之后 | 所有分组标题显示名称和完整会话数量，并预留统一标记栏；展开状态由子项是否可见和操作提示表达，具体动作见交互契约 |
| 标记栏 | Session 行最左侧 2 格 | 管理页面获得焦点时，键盘当前 Session 显示 `> `；其他 Session 保留两个空格 |
| 状态图标 | 标记栏之后 1 格 | 表达空闲、工作、等待输入、待审查、完成、失败或停止；它不表示键盘当前项 |
| 名称 | 状态图标后空 1 格开始 | Session 名称；空间不足时截断 |
| 活动 | 名称右侧 | 当前操作、问题、失败摘要或 Session 摘要；窄宽度下优先隐藏 |
| 时长 | 最右侧 | 工作时长或完成距今时间；不足 1 小时时可以为空 |

- 分组顺序为 Pinned、Needs input、Working、Ready for review、Failed、Stopped、Completed、Idle、Archived。
- 空状态组不显示；Archived 始终显示数量。
- 归档会话只出现在 Archived，不同时出现在其他状态组或 Pinned。

- 所有分组的键盘导航、展开收起、会话打开、预览、归档、恢复和删除统一见[会话管理动作](sessions.md#session-管理列表的动作)。
- 会话预览使用正文区，Session details 使用详情浮层；二者的数据读取与刷新边界由[交互契约](sessions.md#session-管理列表的动作)和[详情架构](../design/tui.md#会话切换预览与详情)说明，本布局文档不维护第二套键表。

| 推荐名称 | 代码名称 | 内容与边界 |
| --- | --- | --- |
| Welcome | `welcome` | 顶部欢迎文字和当前工作区；终端过矮时先缩短这部分 |
| Session 列表 | `sessions` / `SessionManager` | 按状态分组的 Session 行，不要称为 Transcript |
| Session 行 | Session row | 列表中的单个 Session；定位时最好同时说出分组名和 Session 名 |

## 浮层与覆盖顺序

浮层画在普通页面之上，不占用上面那些区域的高度。Session 页面预览替换当前可见页面内容，并保留返回位置，属于页面的只读打开方式，不属于详情浮层。

```text
最后绘制，位于最上层
  字符选择 Screen Selection
  详情浮层 DetailOverlay       ┐ 同一帧二选一
  输入补全浮层 CompletionView  ┘
普通 Session 页面或 Session 管理页面
```

| 推荐名称 | 代码名称 | 怎么认 |
| --- | --- | --- |
| 详情浮层 | `DetailOverlay` | 靠可用区域底部、背景和内容都铺满整行的只读详情层，高度只计算标题和详情，受底部两行上方的内容区限制，超长内容在层内滚动；关闭提示由页面底部 HitBar 统一显示 `Esc to close`，替换底层操作提示，首行留空；打开时阻止底层操作 |
| 输入补全浮层 | `CompletionView` | 输入 `/`、`@`、`$` 时出现在输入框上方的候选列表；有详情浮层时不显示 |
| Slash Command 补全 | `CompletionView::Slash` | 输入 `/` 时显示产品或 App Server 提供的 Slash Command 候选 |
| Mention 补全 | `CompletionView::Mention` | 输入 `@` 时显示文件或 Plugin 上下文候选 |
| Skill 补全 | `CompletionView::Skill` | 输入 `$` 时显示可调用 Skill 候选 |
| 字符选择 | `ScreenSelection` | 鼠标拖选、双击或三击形成的终端字符选择效果，画在所有内容之上 |

- 不要把审批面板、提问面板叫“弹窗”：它们会参与普通纵向布局。
- 只有覆盖在页面之上的 `DetailOverlay` 和输入补全浮层才叫浮层。
- 三种补全是同一个输入补全浮层的互斥内容，不是三个不同浮层；描述具体问题时使用“Slash Command 补全浮层”“Mention 补全浮层”或“Skill 补全浮层”。

## 定位界面问题

推荐使用以下顺序：

```text
页面 / 区域或浮层 / 具体元素 / 当前状态 / 终端尺寸 / 实际现象
```

例如：

- `Session 页面 / StatusLine / 左侧权限模式 / 80×24 / 和模型名称挤在一起`
- `Session 页面 / ChatInput / 第二行草稿 / Vim Normal / 120×30 / 光标位置偏右一格`
- `Session 页面 / Transcript / 标记栏 / Agent 正文单元 / 80×24 / 圆点与正文之间多出一格`
- `Session 页面 / Transcript / 某个工具正文单元 / 展开状态 / PageUp 后内容跳动`
- `Session 页面 / Query / 第三个选项 / 60×20 / 键盘当前项与提示不一致`
- `Session 管理页面 / Working 分组 / foo Session 行 / 100×28 / 时长列被截断`
- `Session 页面 / Mention 补全浮层 / @ 文件候选 / 80×24 / 第一项盖住输入框上边线`
- `Session 页面 / Slash Command 补全浮层 / /skills 候选项 / 80×24 / 第一项盖住输入框上边线`
- `Session 页面 / 输入位置 / Status 面板 / 80×18 / Thread ID 被截断`

如果仍不知道名称，可以说“在 A 和 B 之间的那一行”，但 A、B 尽量使用本文术语。
