# 终端、鼠标与连接恢复

- 本文维护全屏终端、内容区滚动、鼠标捕获、断线恢复和退出行为。
- 产品支持与验证入口见[开发指南](../../tui/README.md#终端生命周期)；要求存在不代表所有终端都已经通过。

## 鼠标规则

- TUI 使用备用屏幕，终端自身的回滚区不保存对话内容。PageUp、PageDown、Ctrl+Home、Ctrl+End 和内容区滚轮浏览对话。
- 内容区与详情滚动是基础阅读能力，TUI 运行期间始终接收带位置的滚轮事件。
- 增强能力是条目点击、悬停反馈、文字拖选与自动复制。关闭增强必须停止这些行为，并清除 TUI 的悬停、按下和拖选状态。

- Enhanced TUI 开启时捕获整屏鼠标。内容区滚轮浏览对话；详情浮层的滚轮只滚动详情；补全浮层不把滚轮传给背景。只有明确命中的控件执行点击动作，其他位置仍可拖选字符。
- Enhanced TUI 关闭时保留滚轮捕获，只关闭点击、悬停、按下和应用内拖选；内容区、详情浮层和键盘正文滚动仍可用。
- 进入备用屏幕时保存并关闭终端的滚轮转方向键模式，退出时恢复；终端宿主必须遵守该模式，不能把输入框滚轮伪装成 ↑ / ↓。输入历史继续由真实键盘的 ↑ / ↓ 访问。

- TUI 进入备用屏幕并绘制完整 Session 页面；退出、失败或挂起时离开备用屏幕，恢复进入前的 shell 画面和光标状态。
- Welcome 是内容区的历史起点；命令、消息、结果和流式正文由同一 Transcript 模型按顺序绘制。
- ChatInput、TopTip、StatusLine、Queue、Goal、Plan 和 Agents 属于固定交互区，不进入 Transcript，也不随正文滚动。
- 内容少于可见高度时，内容区剩余位置保持为空；这些空格只是当前全屏布局，不会被写成终端历史。
- 内容溢出时默认跟随最新位置；PageUp、滚轮向上或 Ctrl+Home 建立稳定内容锚点，Ctrl+End 回到最新位置。
- 增强鼠标开启时，点击正文底部的回到最新控件与 Ctrl+End 使用同一个动作；预览操作自己的内容，详情浮层阻止点击和快捷键操作背景。控件文案与底栏规则见[正文样式](styles.md#正文样式)。
- 到达已加载历史开头后继续向上，读取更早分页；恢复旧会话时仍可从 Welcome 浏览到最新内容。
- 本地命令保存在所属 Thread 的 Transcript 中；后端快照替换用户消息和后端条目时，不能删除或重排其间的本地命令。
- 同一次 TUI 运行中切换 Thread 再返回，必须恢复该 Thread 的本地命令，不能混入其他 Thread 内容。旧消息尚未加载时保留关联的本地记录，加载历史后恢复原位置；显式清空只清空当前 Thread。
- 窗口重绘、调整尺寸、主题切换和相同快照重装只重绘当前页面，不复制 Transcript 条目。

鼠标捕获开启时，事件顺序固定如下：

1. 移动只更新悬停目标并请求重绘，不修改键盘焦点、键盘当前项或候选过滤结果。
2. 左键按下记录按下目标并开始区分点击与拖动；按下目标使用按下色。
3. 发生拖动后立即清除按下目标，进入文字框选；拖动过程中不触发页面动作。
4. 左键松开且没有拖动时，只激活松开位置命中的准确目标；是否转移焦点必须是该控件的明确动作，不能由悬停隐式决定。
5. 松开、Resize、页面切换或目标失效时清除按下状态；指针离开可交互目标时清除悬停状态。
6. Enhanced TUI 关闭时，TUI 只处理内容滚动，不保存悬停、按下或文字框选状态。
7. 内容区滚轮浏览 Transcript；详情浮层的滚轮只滚动自身内容，补全浮层不把滚轮传给背景。移出浮层或关闭浮层后清除悬停、按下和拖选状态。
8. 详情或补全浮层打开时，浮层外的滚轮、点击、拖动和松开均不操作背景；从浮层内拖出会取消当前鼠标手势，重新进入后不能沿用之前的按下位置。

点击和键盘提交必须进入同一个控件动作，不允许鼠标路径直接执行另一份业务副作用。悬停仅用于呈现；命中测试、键盘当前项和动作映射仍由各组件拥有。

## 连接恢复

| 场景 | 要求 |
| --- | --- |
| 传输断线 | TUI 将持久化 Session/Thread 身份交回 CLI，由 CLI 重建连接 |
| 新连接 | 重新读取后端状态及历史，不重放旧连接的待执行请求 |
| 重连失败 | 显示原因及继续原会话的方法 |
| 服务端正常关闭或协议错误 | 不当成普通传输断线无限重试 |
| 草稿、图片与本地队列 | 不能从持久化会话身份推断其可在重启后恢复；该范围仍是[完整性工作](../changes/tui-completeness/README.md)的未决项 |

## 启动、退出与挂起

| 场景 | 要求 |
| --- | --- |
| 初始化失败 | 显示原因，不留下半初始化的终端 |
| 正常退出、系统终止、部分启动失败 | 恢复终端输入模式、鼠标捕获和光标；结束后台任务 |
| Unix 挂起与恢复 | 正确释放和重新取得终端资源 |
| 新增终端模式 | 同步验证获取失败、正常退出及挂起恢复；实现分工见[TUI 架构](../design/tui.md#终端退出与连接恢复) |

## 真实 PTY 测试

测试入口为 `just test-tui <场景过滤器> -- --nocapture`。入口先构建配套的 App Server daemon 和 Windows 所需的执行/沙盒辅助程序，再运行 `zeta-cli` 的 `tui_real_scenarios`；不能用旧 daemon 搭配新 CLI。

TuiProcess 通过 portable-pty 在 Windows 使用 ConPTY、在 Unix 使用 PTY，直接运行真正的 CLI。测试使用独立随机 profile/workspace/Codex 目录及本地 HTTP 服务，通过按键字节、终端字符输出、持久化内容和实际请求判断结果。终端模拟器回送光标等协议查询的应答；等待条件受超时约束，不能仅以固定延迟视为操作完成。

退出时关闭输入和 PTY，让读取线程收到 EOF 后回收；Windows stdio 客户端通过可取消管道读取结束连接，不等待其他写端退出；fixture 结束时停止其独立 daemon。Unix 沙盒命令仍限定 Unix，不能以 Windows 跳过该测试证明沙盒已实测。每次实际结果见[Windows PTY 验收](../changes/2026-09-08-pty-windows/verification.md)。
