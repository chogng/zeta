# 终端、鼠标与连接恢复

- 本文维护终端历史、鼠标捕获、断线恢复和退出行为。
- 产品支持与真实终端验证范围见[开发指南](../../tui/README.md#终端历史兼容性验证)；要求存在不代表所有终端已经通过。

## 鼠标规则

- 终端自身提供的文字选择、复制与历史滚动，不属于 Enhanced TUI。
- 增强能力是 TUI 接管鼠标后执行的条目点击、页签切换、悬停反馈、程序内滚动、文字拖选与自动复制。
- 关闭增强必须停止这些程序行为，并清除 TUI 的悬停、按下和拖选状态；不能以终端仍能选中文字判断增强开关失效。

- 增强 TUI 只控制覆盖浮层内部的点击、悬停、滚轮、拖选和自动复制，当前包括详情与输入补全。
- 凡是占据终端布局高度的区域，包括命令面板、审批、提问、会话管理、会话预览、正文、Queue、Agents、输入框和状态栏，都不参与 TUI 鼠标交互；导航、搜索、翻页、确认和退出使用键盘。
- 判断依据是是否覆盖内容，而不是名称中是否含有“面板”。

没有可见覆盖浮层或增强开关关闭时释放鼠标捕获，历史滚动、文字选择和复制由终端负责。隐藏在命令面板、审批、提问或会话预览后面的补全不启用捕获。终端协议不能按矩形局部捕获，因此浮层打开期间忽略浮层外鼠标事件，不路由到占布局高度的区域。

- TUI 使用终端主屏幕，并在进入时把已有屏幕内容保留到终端历史。
- 关闭鼠标捕获后，滚轮由终端处理，不得转换成面板方向键；VS Code 的 xterm.js 在备用屏幕中会把滚轮转换成方向键，因此不能用备用屏幕承载这一交互契约。
- 退出时保留当前画面并为 shell 留出新行。

- 已完成的正文按对话顺序完整写入终端回滚区，不按当前视口高度裁剪。
- 流式正文只在当前画面更新；定稿后退出当前画面并写入历史。
- 普通跟随最新画面不再重画已经提交的单元，正文浏览才组合定稿前缀和当前可变尾部。
- 窗口重绘、调整尺寸、主题切换和相同快照重装不会重复提交同一份正文。
- 面板、补全、输入框和状态栏不写入对话历史。
- 恢复旧会话时自动读取所有历史分页，再按从旧到新的顺序输出。
- 终端自身的回滚行数设置决定已经写入的内容能保留多久，TUI 不清空终端回滚区。

鼠标捕获开启时，事件顺序固定如下：

1. 移动只更新悬停目标并请求重绘，不修改键盘焦点、键盘当前项或候选过滤结果。
2. 左键按下记录按下目标并开始区分点击与拖动；按下目标使用按下色。
3. 发生拖动后立即清除按下目标，进入文字框选；拖动过程中不触发页面动作。
4. 左键松开且没有拖动时，只激活松开位置命中的准确目标；是否转移焦点必须是该控件的明确动作，不能由悬停隐式决定。
5. 松开、Resize、页面切换或目标失效时清除按下状态；指针离开可交互目标时清除悬停状态。
6. Enhanced TUI 关闭时，终端拥有鼠标，TUI 不保存悬停、按下或文字框选状态。
7. 详情浮层的滚轮只滚动自身内容；补全浮层不把滚轮传给背景。移出浮层或关闭浮层后清除悬停、按下和拖选状态。

点击和键盘提交必须进入同一个控件动作，不允许鼠标路径直接执行另一份业务副作用。悬停仅用于呈现；命中测试、键盘当前项和动作映射仍由各组件拥有。

## 连接恢复

| 场景 | 要求 |
| --- | --- |
| 传输断线 | TUI 将持久化 Session/Thread 身份交回 CLI，由 CLI 重建连接 |
| 新连接 | 重新读取后端状态及历史，不重放旧连接的待执行请求 |
| 重连失败 | 显示原因及继续原会话的方法 |
| 服务端正常关闭或协议错误 | 不当成普通传输断线无限重试 |
| 草稿、图片与本地队列 | 不能从持久化会话身份推断其可在重启后恢复；该范围仍是[完整性工作](../changes/tui-completeness/README.md)的未决项 |

## 启动、退出与挂起

| 场景 | 要求 |
| --- | --- |
| 初始化失败 | 显示原因，不留下半初始化的终端 |
| 正常退出、系统终止、部分启动失败 | 恢复终端输入模式、鼠标捕获和光标；结束后台任务 |
| Unix 挂起与恢复 | 正确释放和重新取得终端资源 |
| 新增终端模式 | 同步验证获取失败、正常退出及挂起恢复；实现分工见[TUI 架构](../design/tui.md#终端退出与连接恢复) |
