# 正文绘制重构规格

本文件保存正文重构的要求。提交 `67603c262` 已引入新的单元模型，见[正文模型](../../tui/src/thread/transcript/model.rs)；本次文档梳理尚未逐项验收，不能把类型存在视为全部要求通过。

## 要解决的问题

重构前，各类正文先转换为通用消息，绘制时再解释角色和可选字段。重构要求每类单元直接提供自己的绘制结果，使测量、绘制和鼠标命中使用同一份内容。

## 单元分工

| 内容 | 单元 | 负责的输出 |
| --- | --- | --- |
| 用户消息、回复、思考、计划、提示和错误 | `ContentCell` | 角色、正文、Markdown、折行、摘要和详情 |
| 用户直接执行的本地命令 | `LocalCommandCell` | 命令输入、提交、运行与完成结果 |
| Agent 发起的工具执行 | 已有 `ExecCell` | 单次或相关调用的参数、实时输出、结果、有界预览和详情 |

本地命令保留用户输入身份，不进入 Agent 工具的分类与合并。执行单元从运行到完成始终在原位置更新，不能完成后换成另一条消息。普通文本内容不需要按每种角色拆成独立文件。

## 验收要求

| 编号 | 要求 | 检查方式 |
| --- | --- | --- |
| AC-1 | 三类单元直接提供绘制结果，不再先转成通用 `Message` | 检查实际渲染调用路径 |
| AC-2 | 流式更新、工具归组增长和执行完成保持单元身份与顺序 | 状态与事件测试 |
| AC-3 | 行高、终端字符和局部命中区域来自同一份结果 | 不同宽度、主题和展开状态下的渲染与命中测试 |
| AC-4 | Transcript 只负责顺序组合、滚动、裁剪、缓存和动作路由 | 检查模块依赖与职责 |
| AC-5 | 折叠预览和详情读取同一份有界数据，并保留上游省略标记 | 截断与详情输出测试 |
| AC-6 | 保持既有历史输出、分页恢复和阅读位置行为 | 正文状态、终端协议和真实 PTY 场景 |

每个具体单元根据宽度、主题、展开和交互状态产生可缓存结果。Transcript 不再包含执行、Markdown 或本地命令专属的绘制分支。Welcome 继续作为 App 提供的页眉，不变成后端消息或正文单元。

其他状态、调度与历史约定沿用[TUI 架构](../design/tui.md)，可见输出沿用[布局规格](layout.md#正文单元会输出什么)。

继续此项工作时需对照本规格登记实际实现与验收证据；当前[完整性验收记录](../changes/tui-completeness/verification.md)仅记录代码更新及待复核状态。
